# Navigation 架构草案

状态：2026-10-06，0.11.1修复诊断存储配额与迟到渲染通知；0.9.0接入AutoNaviMapView交互原语；0.8.0修复内容布局，并按用户要求采用无持久化、无澄清的独立查询。当前查询交付修复与验收入口归[查询交付任务](../tasks/query-delivery/packet.md)，此前生成原语证据归[动态界面任务](../tasks/agent-generated-ui/packet.md)。早期Trip确认、读回与恢复只是历史行为，对应[能力任务](../tasks/capability-boundary/packet.md)与[交互任务](../tasks/interaction-integration/packet.md)，不作为当前产品要求。

## 独立查询与职责

用户提交一句出行要求，应用建立本次运行状态并请求可用工具。每次查询都新建位置、来源、约束、候选和模型消息历史；不保存结果、不恢复旧行程、不跨次续接，不通过问题澄清等待用户回答。用户终止后不再派发本次后续工具，迟到回调不能改下一次查询。缺少数据时，Agent可以查询公开资料、提出有依据的目的地假设或说明具体缺失，不能用上一轮资料补空白。

MiniMax M3理解目标、选择工具、关联来源并生成原生界面。确定性工具处理真实坐标、供应商候选、费用和时间，返回检查结果；模型不负责凭空计算路线。一次查询的到达期限从收到该指令时起计算，查询和渲染消耗的时间也计入，不能为显示可行而改起算时间。

固定外壳只保留输入框和查询／终止按钮，任务结果由Agent生成。查看候选和加载地图属于本次界面的本地操作，不建立新的问答会话。view_route只选择父应用的当前查看状态；生成稿必须通过on_facts_changed或自己的本地控件逻辑呈现所选路线内容。仅发送事件不会自动出现宿主详情卡，技能示例应说明完整交互责任，不能把“已选择”提示当作详情展示。详情可用原生View与set_visible切换到独立页面，并提供返回操作；保留列表控件实例，不重建列表。有限页面高度应取生成区域实际可用视口，长详情使用自己的滚动区域。技能中的完整示例用于说明可运行语法，不是要求Agent采用固定节点、页面结构或路线详情组件。锁定版本Modal和StackNavigation未提供Splash打开／关闭或push／pop方法，不能从类型已导出推断方法可调用。当前不保存Trip、不执行导航、不持续观察交通。未来的能力层、长期偏好和跨应用资料整合是产品方向，不能因此在此阶段引入用户记忆或持久化任务。

## Agent工具调用与展示

应用通过官方net.http_request调用MiniMax-M3非思考模式。一个本次运行内的会话保留原始assistant消息及全部tool_calls，顺序执行并分别追加对应tool_call_id的role:tool结果，再继续模型。工具不自行请求另一个模型，不通过动作封套或阶段许可表安排顺序。assistant无工具调用即结束本次运行；终端content仍保留在本次消息历史和facts.answer中。结果只用一个展示通道：收到同稿原生rendered通知并确认实际诊断没有错误后，锁存本稿成功状态；通知迟于render_ui诊断回执或终端回复时也重新核对并更新显示，展示生成稿并隐藏宿主纯文本；没有可用生成稿且终端文字非空时显示文字兜底，隐藏失败稿的父区域但不销毁子实例。开始mount和排队通知均不等于实际执行成功。成功状态只在新稿或清空时复位，后续局部事件错误继续反馈并保留已有稿，不把整区切到文字兜底；首次执行失败仍可显示终端文字。代码块仅按文字显示，不抽取执行；空回复且没有生成稿时明确报告未返回可展示内容，不以“查询完成”替代结果。下一次输入新建会话。

定位、地点查找及采用、公交／驾车查询、确定性候选比较、技能读取与render_ui各有独立参数。元提示简述单次查询目标、实际工具和呈现通道；技能正文从应用包按需读取，不全部塞进system，也不规定先读资料再渲染的顺序。可处理工具失败回到同一历史，传输失败明确呈现，不隐藏重试。没有应用自设的工具步数、输出大小、自动阶段或纠正次数上限。

render_ui以完整源码替换本次生成稿，执行模型生成的Splash／Makepad源码；原生诊断作为工具结果由Agent处理。success只表示没有已报告的执行错误，不证明地图、详情或用户任务已经完成。首次挂载先给子Splash有限高度再安装源码；尚未绘制或零面积的子几何回退到父内容视口。父区域刷新不得重新构造活跃的子Splash，否则即使同名和同正文也可能丢失子VM与本地状态。模型请求失败显示安全的具体运行原因，不误称生成界面失败；已有结果与原生诊断仍保留。修正中的用户反馈使用简短状态，原始堆栈与属性类型错误留在工具结果和宿主日志；后续渲染成功清除反馈，不能把诊断压掉后假装执行成功。应用不改写生成稿，不使用预制分区或控件树协议，不设白名单、图数或层级限制。宿主提供真实滚动视口；viewport表示最近绘制的可见区域，不是整页内容高度上限。技能说明Fit的内容自然高度、Fill的剩余空间含义，以及Label显式换行语法；滚动和文字换行是不同机制，不能用增加ScrollYView代替正确内容尺寸。具体嵌入接口以当前源码和实际验证为准。

原生动态查找、子实例和几何来自锁定宿主覆盖。Splash.diagnostics在set_text前启用实例捕获，重复读取不消耗、每稿清旧记录并保留宿主日志；try已清除的异常不能恢复。rect返回最近绘制裁剪area，未绘制为nil，不在render借用期间同步查询。Navigation使用局部无衬线字体，其它应用主题不变。验收基准为macOS宿主Android手机模式，不能称Android真机。

官方app peer有入口，但锁定版本不能执行应用脚本工具，本项目不借清单支持宣称已接通。现有M3 HTTP与OctoScript层维护标准工具历史，不增加kernel或SDK后端；事实与版本归[资料核对](sources.md)和[工具链说明](../toolchain/README.md)。

## AppCard复用评估

锁定OctoSense的apps/appcard是独立Rust助手模块，通过Octos kernel会话进行领域路由、L0生成检查与卡片渲染。当前构建只启用app-hub，未启用app-appcard，启动器也未提供kernel。Makepad widgets的appcard feature与该助手不同，在锁定版本中为空feature；相关控件存在不代表助手已接通。

AppCard provider registry含MiniMax-M3配置，但这只说明配置可识别，不证明现有私有HTTP配置或工具可以直接使用。其backend/octos_ui.rs当前tool_context为空，send_tool_result不回传客户端结果；不能直接承接Navigation的read_skill与render_ui异步结果。内部route_to_app是助手领域路由，不是已验证的第三方应用工具调用。其生成修复保留原始意图，当前Navigation的同次完整工具历史已承担这一职责，本轮不重复实现，也不搬入L0检查器与纠正次数预算。

本轮评估决定保留现有标准HTTP工具循环。完整AppCard迁移需要kernel配置和工具执行桥，属于独立范围。重新评估的判别是：隔离AppCard会话通过实际M3完成技能工具结果返回、原生render_ui诊断返回，并在同一历史中修正界面；仅注册模型或生成静态卡不能证明闭环。以上是锁定源码调查与工程决策，未构建或运行AppCard。

## 可用来源与真实位置

正常live模式只使用本次实际取得的位置及公开地点／交通资料，未接入真实日历和笔记账户，不提供模拟文件作为个人背景。没有日历能力不等于用户没有行程；没有机票时机场可以是可说明、可在新查询中更改的推断，航站楼未知不能补造。显式demo模式才提供独立日历、笔记和模拟位置，保留mock性质、标识与时间，不预先整理为包含全部答案的背景文件。

真实位置由获授权的location.get一次取得CoreLocation WGS84样本。宿主先通过真实系统权限API等待授权决定；获权后才开始最多15秒采样，权限等待不消耗采样和请求超时预算。系统授权与宿主sheet按独立原因暂停请求时钟，拒绝、终止或迟到授权不会重新启动已结束的采集。样本年龄最多60秒、精度半径最多100米；取消、关闭、失败或超时停止采集，不在真实失败后自动回退模拟。应用保留真实采样时间和精度，再经高德转换为GCJ-02并核实起点城市。目的地城市独立核实，跨城查询不从演示数据回填城市。来源解析可以确定性处理，任务相关性由Agent理解，来源文本不能伪装成用户明确指示。

机场搜索使用高德类别150104，当前城市是查询偏好而非城市限制。采用本次真实返回的地点、坐标和类型，不生成POI标识；类别和父子关系不保证特定客运入口适用，不能凭空补T3或国内出发。币种依据实际地域与供应商人民币计价推断；无法换算明确外币时报告能力缺失，不改写用户金额。

## 路线、费用与地图

候选保留交通方式、起终点、等待、距离、费用、耗时、步行量、来源与查询时间。金额使用整数分，时刻使用绝对时间；未知票价或叫车等待不等于零。模型可以比较费用、耗时、疲劳等目标，当前实现以用户分钟数与预算的明确数字条件为主，不能静默放宽。

除供应商完整OD候选外，应用维护本轮真实地点和路线前缀。节点来自起终点、地点查询和实际公交上下车／经停站；extend_route按Agent选择的前缀、目标节点、方式及公交策略查询一整段，代码计算出发时刻、核对实际几何连接并累加金额。完整公共交通边可以自带换乘和步行，票价只能使用新查询的完整区间报价，不能从全程票价按距离或站数裁分。单次出租车报价不按距离裁分，不与公交已覆盖费用重复相加。地铁图策略需要真实两端站点POI ID，未取得就说明缺失。

前缀可以继续扩展为打车接公交、公交接打车、两端或中段打车，不硬编码这几种模板。时间依次累计；有未知候车时后续公交只按最早到站场景查询，不能证明实际赶上该班次。费用完整时输出整数分总价，缺价时保留已知小计作为下界；预算、期限和未核衔接分别说明，不用严格feasible=false掩盖已取得的真实估值。模型决定扩展哪些真实节点，不能替代码填坐标、拼价格或改变原截止。已查范围与候选边保留在本轮facts／开发trace，不保存到业务历史。尚未找到成立候选只能说明当前查询范围与原因，不能证明现实不可达、穷尽全部路径或全局最优。

高德出租车使用单路径驾车请求，将route.taxi_cost（元）明确对应到所查询路径；这是传统出租车估算，行驶时间不含已核实叫车等待，也不是网约车车型报价。多路径的route级估价不能当作各path单独的报价。

滴滴接入复用正式MCP服务，仅提供地点搜索与价格预估。search_didi_places保留供应商实际地点ref，quote_didi使用这些ref查询车型，保留原priceText及可精确解析的整数分；无法解析的显示文本保持未知，优惠单列。attach_quote按两端真实名称、城市、地址和入口／航站楼的语义依据，将选定车型估价替换明确出租车leg旧价，派生新前缀并重算；原前缀不变，价格不重复相加。关联依据是假设，不把不同提供方坐标当成已统一，不修改高德几何或认证滴滴上下车连接，仍保留未知等待与未来价格变化。供应商eta没有已核单位，不转成分钟作为准时依据；不调用下单接口。

官方Android和JS SDK分别依赖平台运行环境。当前OctoScript宿主未验证可直接使用的SDK桥，Android显示模式不等于Android运行环境。本轮保持官方REST的薄请求和必要归一化，不另造通用高德SDK；地图UI恢复时优先验证官方SDK可嵌入路径。高德MCP概述也不足以证明本任务全部时刻／费用／几何参数，未迁移既有路线服务。

AutoNaviMapView是锁定宿主覆盖提供的通用原生地图视口，复用Image纹理，不是官方MapView类型的别名。原生控件只管理GCJ02相机、实际绘制尺寸、手势与图片，不持有业务路线ID。应用map事件绑定候选，fit_bounds以全部真实几何及端点取景；camera回调驱动现有高德代理显式请求location／zoom／size、scale=1及同源paths／markers。地图交互不调用M3，不保存视口。底图刷新有网络延迟，这是可更新的raster视口，不是连续瓦片、离线地图或导航SDK。

单指拖动即时变换已加载纹理，释放请求新区域；双击或zoom_by改变缩放，页面可提供放大、缩小和全路线按钮。越出旧帧的区域使用背景，不能拉伸边缘伪造地图。相机按scale=1实际高德图片验证的512像素Mercator基准计算，请求图片尺寸与绘制矩形同比匹配。接口尺寸／zoom范围遵从供应商，不将这些范围作为应用城市限制。首次或换目标重新取景并清旧帧，同目标返回保留相机。每次相机请求的native编号贯穿HTTP结果与原生解码安装，旧回调不得把旧图装到新相机；延迟派发只执行仍对应该编号的任务。

真实几何只在共享端点无损合并，缺段不补直线、不相接的段保持分开。高德[静态图接口](https://lbs.amap.com/api/webservice/guide/api/staticmaps)最多支持4个折线／多边形，不能据此截断候选几何。即使HTTP200也可能返回业务错误JSON，显示实际错误，保留当前加载／错误状态，不把旧帧标成新视口成功。旧Image接口仍支持静态图片，不能称其可拖动地图。原生手势、跨解码编号和真实标记位移的证据归[交互地图任务](../tasks/interactive-map/packet.md)，M3生成表现与原语验收分别报告。

地图失败不改变候选计算，这不是连续导航。历史Maps选择返回契约属于本仓库宿主覆盖；当前查询不提供该交互、不申请maps能力，不因此宣称stock宿主已有任意应用联动。当前应用以设备位置为起点，不支持任意手选起点。

## 运行材料与开发记录

应用不保存查询结果、Trip、用户历史或模型会话，也不在启动时读取旧结果。输入来源文件、打包技能和凭据配置属于运行材料；必要子实例通信只服务当前run，不用作恢复。宿主和开发工具的日志、隔离验收证据不是业务存储入口，开发记录按各自忽略边界保存。

启动器从.env生成隔离宿主profile和本应用私有配置，目录0700、凭据文件0600。应用读取高德、M3与可选滴滴MCP key，模型key只用于Authorization header，滴滴key只用于正式MCP鉴权URL，不进入bundle、模型输入、UI或记录。当前模型地址固定为已验证的https://api.minimax.cn/v1，不自动更换模型或提供方。实际HTTPS主机在manifest声明，网络失败不能把带key的URL或私有配置回传模型。构建、覆盖补丁和挂载一致性由工具链锁文件与实际源码维护，不能把包预检当作应用行为验收。

开发诊断由启动器显式启用，正式配置默认关闭。启动器为一次开发启动生成 session UUID；每个脚本实例在同一宿主 UI 线程同步领取序号，查询沿用 run_id，事件以实例内 seq 排序。各实例独立写入私有 jail 的 dev-trace 目录，旧实例不会覆盖当前实例文件。固定外壳中的开发态透明标记提供实际实例身份，读取工具只采用唯一有效可见标记，不读取生成内容的同名控件或按文件时间选择。编号领取失败时关闭记录并报告诊断错误。

模型请求先序列化为不可变正文，该正文同时用于派发和记录；单独的派发事件区分已准备与实际进入网络调用，响应保留实际收到的正文。工具事件携带 tool_call_id；渲染源码、原生诊断、本地交互及地图请求状态来自实际执行入口，不通过最终界面反推。事件在独立定时入口通过fs.append追加到分段JSONL，按宿主单文件1MiB上限换段，避免每事件创建文件耗尽整个jail的256条目配额。大于单文件上限的事件不截断伪装完整，实例状态与导出必须标明不完整。读取兼容旧事件文件，并核对序号与分段尾部完整性；记录写入失败不终止业务。新开发启动在既有停止实例的边界将旧诊断完整迁到私有build保存，腾出应用存储配额，不迁活跃记录或业务材料。没有恢复入口，不把日志重新喂给模型。鉴权头与服务 key 不记录，已配置 key 的原值和 URL 编码值在写入前移除；导出再次检查精确凭据。原始日志仍包含任务、位置及模型内容，属于本机私有开发材料。

原生执行预算中止可能直接退出脚本入口，不能保证触发应用catch或产生tool_result。当前实例导出同时保存同一启动器的宿主日志，并在状态中记录其来源；日志先通过精确凭据检查，再以私有权限写入。显式历史事件导出若没有对应启动器日志，不拼接当前宿主日志，也不伪造应用错误事件。
