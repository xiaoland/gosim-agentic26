# Navigation 架构草案

状态：2026-10-01 技术草案。产品已确定通过用户手机既有应用完成 Navigation 帝王蟹能力层任务；下述路线求解、跨应用上下文、偏好学习、手机操作、Agent 和宿主集成都尚未实现。具体应用、操作通道与运行载体仍需调查和设计。初赛机场演示及运行时按需生成工具的验收建议归[当前任务](../tasks/capability-boundary/packet.md)，实现方式尚未定案。

## 职责

1. 既有地图或系统界面承载地点选择、候选方案、来源、确认与导航交互；具体呈现和接入方式由目标宿主能力决定。目前的 OctoScript 本地约束草稿只用于开发调试，不预设为产品主入口。
2. Agent 结合自然语言和已授权的背景、偏好形成可验证约束，并解释工具给出的数值；不得自行编造路径、费用、时刻或执行结果。
3. 确定性规划器输入约束与有时间戳的交通数据，输出可行候选和约束检查结果。没有可行路线时返回不可行原因，不静默放宽时间上限。
4. 手机应用操作工具从用户既有应用取得当前行程、位置、公交/地铁方案、票价及打车估价，并保留应用、页面和读取时间。应用本身查询服务；本项目不接入这些服务的 API 或绕过应用调用其后端。应用没有提供的数据保持未知，不能由 LLM 补造。
5. Trip 状态机记录 proposal → confirmed → active → completed/cancelled；来源变化或过期产生 needs_replan，替代计划需要新的确认。未来宿主能力以实际运行验证为准。

## 能力层的待设计边界

能力层需要补充出行相关的数据与操作，而不是要求用户手动把其它应用中的内容搬进草稿。跨应用上下文负责取得已授权的信息并保留来源、时间和适用范围；偏好学习负责把用户明确设置与从选择中推断的偏好区分开。两者是职责说明，不预先要求拆成独立服务或引入通用用户画像框架。

按需生成的工具同样受手机应用边界约束。它可以把观察到的应用操作实现为可验证、可复用的程序，不能临时引入地图或日程服务客户端来绕过用户要求。底层如何读取页面、操作控件或使用应用公开的动作，须在所选手机和应用版本上验证；当前未具备这样的操作通道。

航班时间、行李或本次天气是具体任务背景，不自动变成长期偏好。如何表达推断的可信程度、过期条件和用户修正，是下一轮设计需要解决的问题。信息缺失或来源冲突影响到达期限、预算等关键约束时，应澄清而不是用猜测掩盖。

第一条完整任务需要能证明：用户少输入仍可形成正确约束，系统取得的数据有来源和授权，求解结果满足约束，并在上下文被纠正后重新计算。实际接入方式须先核对目标宿主与手机应用的可操作能力，再形成工具约定。

## 路线模型

- 地点节点要包含换乘/上车/下车位置；经纬度与搜索显示名不能互相替代。
- 路段记录 mode、起终点、出发/到达时刻、等待、距离、费用、步行量、数据来源与过期时间。
- 搜索状态除了节点和时间，还可能需要票制状态、当前乘坐服务和打车段状态。简单把每条边价格相加，会重复收取出租车起步价或遗漏公共交通优惠。
- 打车费用按一次连续打车行程计费；接入实时估价前只能显示明确标注的 fixture/估算，不能宣称真实报价。
- 第一模式是在到达截止前最小化总费用；最快、疲劳偏好、最晚出发在基础模型验证后扩展。“最慢”含义仍待决定。
- 支持费用、耗时、疲劳、换乘、可靠性的非支配候选。支配剪枝只有在时间相关性和票制状态可比时才成立。
- 金额用最小货币单位整数；时刻用含时区的绝对时间；费用估价区间与未知票价不能冒充精确值。草稿界面的分钟预算仅用于初始化，后续迁移为 departure_at / arrive_by。
- 机场演示的时间上限从收到指令时起计算，查询、生成工具和确认消耗的时间也计入。手机界面只能给出有限候选和估价时，结果表述为已核实候选中的最低估价，不声称全局最优或保证实际费用与到达时间。

## 第一条完整任务建议

从已授权的日程、位置及偏好形成到达期限、预算等约束，只澄清关键缺失信息 → 获取一组有来源的候选路段 → 算出全公共交通、全打车、公共交通接打车候选 → 在既有地图或系统界面显示取舍和不可行原因 → 用户确认 → 写入 Trip → 注入一个明确标注的延误事件 → 旧计划失效 → 重算并确认 → 重新读回 Trip 验证。

上述是长期完整闭环。初赛建议先完成当前任务中的手机应用操作与结果核验；偏好学习和持续重规划不预设为本轮必需范围。可复现 fixture 可单独验证求解器与状态机，真实演示数据则必须通过既有手机应用取得，两种证据分别记录。后续必须有混合方式获胜、时间不可行、出租车起步价、延误后旧授权失效等测试。

当前锁定文档明确：card-host 不提供 host services；通过 gate 声明某项能力并不意味着设备上存在实现。后续接入 Agent 前，应读锁定版本的 AI-SERVICES.md 和目标宿主代码，并跑真实调用测试。模型凭据留在宿主或服务端，不能放入 bundle；地图、出行和日程账户由用户手机上的既有应用管理，本项目不另行接入。
