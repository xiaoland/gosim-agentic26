# 0.2 交互与应用联动方案

状态：2026-10-04，用户已确认本方案并授权“开始实现”。下文为实施目标和验收门槛，不表示功能已经完成。0.1 已验收并推送为 `c99f50e`；现存未提交草稿不属于验收版，也不自动纳入本方案。

## 推荐的产品形态

让一句话、地点选择、路线卡片与地图围绕同一趟出行工作。Agent 负责从可用背景补全并查询；用户可以直接点地点、比较路线、纠正和确认。输入框继续适合表达目标和补充信息，不要求用户用文字操作所有控件。0.1 的“两按钮”是临时收敛，不是 0.2 的设计限制。

建议第一条体验为：输入“40 分钟内到机场，预算 50，尽量便宜” → 自动取得位置和目的地依据 → 展示可纠正的目的地 → 卡片比较实际候选，点选同步地图 → 确认所选方案并读回。确认只建立行程，不能把它显示为已经叫车、已开始导航或已创建提醒。

交互优化可以在现有 OctoScript 应用中完成。真正应用联动优先选择“在独立 Maps 中搜索并选择地点，返回 Navigation 继续规划”。它复用现成可操作的官方界面，与本次地点选择 UX 直接衔接。日历读取更能减少表达，但最新 Calendar 仍缺事件查看/编辑界面及跨应用授权通道，放在后续上下文里程碑。不能把同应用地图组件复用算成跨应用联动。

## 一、UI/UX 的落地设计

| 环节 | 建议的操作和呈现 | 为什么这样做 |
| --- | --- | --- |
| 发起任务 | 一句话输入；开始后显示实际阶段及终止入口。 | 用户不用先填写地点、时限、预算表；阶段来自工具状态，不显示虚构百分比。 |
| 核对地点 | 起点、目的地可点击；目的地旁区分“来自日历”“你选择的地点”“根据位置推断”。 | 自动补全可见且可纠正，机场 POI 不冒充机票或航站楼入口。 |
| 选择地点 | 原生弹层内搜索、显示 POI 名称/地址/城市、地图预览，明确选中再采用；允许跨城。 | 不让模型替用户决定点击结果；重名地点有足够信息区分。 |
| 比较方案 | 默认突出两至三条有差异的候选；费用、预计到达、耗时、步行/换乘与交通方式顺序直接可见，全部候选可展开。 | 减少八段重复文字；不能为了凑卡片生成路线或隐藏失败候选。尚未取得的步行量、费用等显示未知。 |
| 查看路线 | 点卡片只切换所查看路线和地图；主要换乘点有对应分段说明。 | 选中查看与确认分开；地图和卡片共用候选 ID 与几何，不重新算另一条路线。 |
| 无解与中断 | 完成负例显示“本次已查候选均不满足”，突出最短已知/最低已知及各自缺口；中断显示尚缺哪些数据。 | 最快与最便宜可能不是同一条路线；未知费用不等于超预算，部分结果不等于无解。 |
| 修改与继续 | 可改地点或单个约束，也可自然语言补充；改预算不重置到达期限。停止后保留结果，继续时重检过期数据。 | 不要求重打一整句指令；用户等待、纠正与继续仍消耗原期限。需要从现在重新计时必须明确表达。 |
| 确认 | 明确“采用这个方案”，再次检查期限、来源及路线时效，保存并读回。 | 卡片选择不产生外部操作；确认过期方案要说明原因并重查。 |

窄窗口采用地图概览与紧凑卡片上下排列；宽窗口可并排。默认露出地图、主要结论和代表候选，出处及完整失败理由按需展开。费用未知、航站楼不明等会改变选择的事实始终可见。卡片选中状态不只用颜色表达，支持键盘选择、焦点返回和清晰的按钮名称。

地点选择需要业务接口配合，不能只增加一层 UI：当前 `select_destination` 的自动机场假设分支限定机场类别。显式用户选择应作为独立、有来源的目的地输入，核验真实 POI/坐标及城市；保留自动机场推断自身的条件，而不是统一删掉类型检查。原始 GPS、用户指定起点及地图落针也应有不同来源。第一步先做 POI 搜索选择；自由落针待坐标回传及逆地理编码验证后再承诺。

卡片渲染使用确定性候选数据，LLM 只补充简短解释。点击候选直接指定 `route_id`，不再让模型解读“选方案二”。新目的地或约束改变时旧候选失效；迟到网络回调不得覆盖新选择。地图展示的取样、压缩不改变用于端点和费用校验的原始路线数据。

### 地图实现的选择

**建议 0.2 首次落地使用高德同源地图概览，加 Makepad 原生地点选择器与卡片。** 已用现有 Web 服务配置、官方文档公开坐标取得 640×360 的标记/折线 PNG，并实际查看。这样沿用路线的 GCJ-02 坐标，不先增加另一套地图服务和坐标逆变换。随后已在固定宿主的隔离应用中，用 `fs.read_bytes` 与 `Image.load_image_from_data_async` 实际显示同一 PNG；一次构建、零修复，未启用网络或复制用户数据。真实用户路线的几何提取、在线图片下载与候选切换尚未组成端到端验证。

通过 `net.http_request` 取得图片字节，再交给原生 `Image`，不要将带 key 的地址放进可见链接或直接作为会在失败时输出地址的媒体 URL。地图请求与行程查询分别标识；切换卡片时旧图片回调不能覆盖当前候选。地图失败只影响展示，已取得的合法路线仍可比较，界面明确“地图暂不可用”。

高德静态图最多四条 paths、十个 markers，单图最大 1024×1024。概览可突出一条所选路线，按需看分段；不能为了满足数量限制用直线补齐缺失交通段。超长几何的展示简化需保留端点和换乘点，原始数据不变。保留地图提供方署名。这一方案是地图概览，不宣称支持平滑拖拽或点击任意点返回经纬度。[官方静态地图文档](https://lbs.amap.com/api/webservice/guide/api/staticmaps)

原生 `MapView` 是第二条可研究路线。官方 Maps 已使用它和 `set_nav_polyline`、`set_route_markers`，但当前脚本层的自由选点接口、底图与高德坐标对齐尚不完整。不能直接复用 Maps 的默认 San Jose 起点、无 GPS 时模拟车辆进度，或用 `sys.navroute` 的另一条路线替换已选高德公交/混合候选。要采用它，先验证坐标对齐、脚本事件、视野适配与断段呈现；失败应如实收缩为概览，不画错位的“真地图”。

## 二、应用联动的实际路径

调查分开看固定宿主与最新官方源码。当前固定 OctoSense 为 `d405d5c`；默认应用列表的缺口不能泛化为整个生态。最新官方版本已经增加 Calendar，但存在应用所有权与权限限制，不能仅升级后就展示“已接通日历”。

| 目标 | 已查到的能力 | 0.2 的处理建议 |
| --- | --- | --- |
| 日历 → Navigation | 新版有 Calendar bundle 和服务；服务只接受 `os.calendar`，工具默认不跨应用共享，Navigation 没有可直接使用的 calendar capability。 | 作为后续减少输入的上下文联动；需同时补齐 Calendar 用户操作面、只读授权及有时间范围的事件读取，工作量超过单一接口。 |
| Navigation ↔ Maps 选点 | 固定版 Maps 搜索、地点页和地图视图可运行；没有已证实的选点请求/回传契约。 | 首条真实联动候选：复用独立 Maps 已有搜索结果选择，补窄请求/回调。范围只含选点返回，不含自由落针或混合导航交接。 |
| Navigation → 提醒 | 新版存在原生 Reminders 模块及部分可共享只读工具；当前 `app-hub` 构建未启用该原生 feature。 | 读取已有提醒不等于创建提醒。创建、取消和实际触发都需独立接口及证据，放在确认行程之后再做。 |
| Mail → Navigation | 固定版服务存在；账户按调用应用授权。隔离实验已验证空账户、原生登录表单打开与取消。 | 作为可选背景源，不因接口现成而替代日历目标；无账户时无需先配置。读取正文会标为已读，不能称作纯只读接入。 |

日历作为后续里程碑的验收闭环为：在 Calendar 中有一条用户可查看、可修改的出行事件 → 用户允许 Navigation 读取相关时段 → Agent 得到带事件 ID、时间、地点和来源的资料 → 关联此次机场任务 → 界面显示依据 → 修改/撤销事件后重新查询，旧背景失效。日历事件并不自动等于机票；航班起飞时间不能自动当成抵达机场期限，缺少值机提前量时应保持两者分离。

该链路需要三处都成立：Calendar 的用户操作面、授权读取通道、Navigation 的来源适配。尚不能读取的事件保持缺失，不退回私有文件直读；多条冲突行程需要展示候选及简短澄清，不默认第一条。测试可在隔离 Calendar 中创建明确的测试事件，但要展示它由真实应用写入和读取，不能预合并为带答案的背景文件。

### 首条联动：独立 Maps 选点返回

用户点击目的地旁“在地图中选择” → OctoSense 打开独立 Maps 的选择模式 → 用户搜索并选择一个结果，查看名称及地图 → 点击“使用此地点” → 返回 Navigation，界面标为用户选择，按原预算和期限重新规划。取消返回原行程；不要求重新描述地点。

**这需要新增一条窄宿主桥及 Maps 脚本适配，当前官方版本没有现成接口。** 提议接口只承载地点选择请求/结果，不先建设通用消息总线。改动面为宿主的请求关联与前台切换、Maps 的选择模式及完成/取消回调、Navigation 的发起与结果接收；同时补齐实际需要的调用许可和返回调用方检查。服务名称和具体调用签名待实现时按官方接口约定确定，下列数据只是协议草案：

- 请求保存由宿主识别的调用方、请求 ID、当前目标或搜索提示，以及有效期。调用方不能通过参数伪造另一个应用身份。
- 返回结果包含相同请求 ID、名称/地址、坐标与坐标系、来源和选择时间；如果原搜索没有稳定 POI ID，就不虚构 ID。取消、拒绝、不支持和超时各自返回明确状态。
- Maps 搜索结果若为 WGS84，先复用已核验的高德坐标转换，并核对地点城市/计价依据；不能直接写为 GCJ-02。用户选中一个机场坐标仍不证明航站楼入口。
- 一次请求只接受一次有效返回。终止任务、换目的地或新查询后，旧返回不能改当前行程；关闭 Maps 应能回到原任务。

首个实现前实验只验证公开地点的往返，不调用模型、不重新算路线：Navigation 发起 → 独立 Maps 选择 → 同请求返回，随后验证取消及旧请求失效。先给这个实验一个独立、有限的实施范围；若它牵涉通用消息总线或大规模运行时重构，保留接口提案，不把未经验证的桥变成初赛前置。将来再讨论“查看既定路线”的交接；打开应用本身不等于已开始导航。

Calendar 后续若接入，针对当前 M3 直连工具循环，优先窄只读 `host.request` 扩展。不能只删掉服务的 owner 限制：必须检查真实调用方的授权，仅开放有时间窗口/数量边界的事件读取，写操作仍属 Calendar。走 `shareable` + octos broker 可以复用官方委派模型，但会引入另一套 peer、模型轮次与授权流程，应在需要系统 Agent 编排时再评估。独立 Calendar 还需最小新增/查看/修改事件界面；直接把 fixture 写入它的私有文件不能算用户完成了跨应用操作。

## 官方工具与生态的分工

| 项目 | 对本作品的具体用途 |
| --- | --- |
| Makepad | 原生输入、弹层、地点行、可点击卡片、滚动和图片/地图展示；不把 HTML 讨论原型作为最终技术栈。 |
| OctoScript | 实现任务状态、交互事件、受约束工具调用与结果呈现，继续作为参赛应用交付。 |
| OctoSense | 承载应用、位置与账户服务，提供真实跨应用授权和数据交接的边界。 |
| App Hub / Design Flow | 使用固定兼容组合打包、检查、截图和复现；控件示例和文档中的概念需核对实际运行。 |
| octos | 后续跨应用工具目录与授权委派的候选运行通道；目前 M3 直连循环已经工作，不为名称上的接入更换模型或重写整条链路。 |
| octoscode / OctoLoop | 可用于有界实现、运行反馈与独立审查；开发工具使用记录与应用本身的 Agentic 行为分别举证。 |

官方课程说明各项目按选题组合，并不要求全部接入。应以用户少输入、能核验结果为标准判断接入价值；Rinx、hagency 等不因属于赛事生态就变成当前 Navigation 的依赖。[官方课程与项目分工](https://github.com/gosimfoundation/hackathon-agenticapp26/blob/main/docs/curriculum.md)

## 实施顺序与验收门槛

| 顺序 | 有界工作 | 完成依据 |
| --- | --- | --- |
| 1 | 明确本稿交互及联动范围；评估已有未提交草稿。 | 方案获实施授权；0.1 仍有可重现基线。 |
| 2 | 地点选择、候选卡、单条所选路线地图概览；整理确认入口。 | 不读用户数据的原生组件实验通过；真实候选卡、地图和保存结果 ID 一致。 |
| 3 | 修复影响交互的已知边界：派发阶段、来源标签、确定性结论、停止/继续。 | 有方案、无合格候选、服务中断、过期确认、目的地纠正的实际行为通过；原期限不被无意延长。 |
| 4 | 独立验证 Maps 搜索选点往返桥，随后接入真实规划。 | 独立 Maps 中实际选择公开地点后，Navigation 收到同请求结果；取消、关闭与旧返回不污染任务。应用包与所需宿主版本明确配套。 |
| 5 | 在已通过的版本上录制端到端演示。 | 一句输入、地图比较、纠正/确认，以及一个真实失败或空状态；标明模拟来源和未实现操作。 |

考虑 10 月 4 日 23:59 的初赛截止，建议优先保证步骤 2–3，不把升级整个宿主、完整地图导航和多个账户接入同时压入同一个版本。Maps 往返设独立通过门槛；如果它需要的宿主改动超过初赛范围，交付已验证的 UI 改善，并明确真实联动仍待完成，不用假按钮补齐叙事。

最小验收集还应覆盖：同名/跨城 POI 不误选；改预算不改原截止；点另一张卡不触发重新规划或保存；未知价格不显示为零；地图缺段不补直线；地图加载失败仍能读卡片；旧请求不覆盖新任务；确认失效方案不写 Trip。是否完成不能仅由离线断言数量或 LLM 自述决定。

## 本轮证据与剩余讨论

研究产物在 `build/research/interaction-integration/`，不属于参赛包：`ux-study/index.html` 是可交互合成原型；`static-map-study/evidence.json` 是一次公开坐标的地图服务结果；`app-surface-study/summary-safe.json` 记录隔离原生应用入口及 Mail 授权表单取消；`app-surface-study/image-probe/evidence.json` 记录原生 PNG 展示。最新官方接口的精确 revision、位置与失败边界归 `interop-study/report.md` 和 `interop-study/sources.json`。它们分别证明交互想法、服务可用和宿主界面，不互相替代。

用户已同意纳入“独立 Maps 选点返回所需的窄宿主扩展”。先完成完整交互闭环，再以独立通过门槛整合该往返；日历上下文、自由地图落针、写提醒和持续导航按实际价值依次扩展。本稿不请求邮箱密码、验证码或私有日历内容。
