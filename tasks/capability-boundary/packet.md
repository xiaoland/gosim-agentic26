# 一句话机场 Navigation Agent

状态：2026-10-01，初赛在深圳交付使用 MiniMax M3 的 OctoScript Navigation 应用，允许直接接入服务。用户已配置 `.env`；隔离预检通过 M3 原生工具往返及高德地点、驾车、公共交通、步行接口。当前仍未进入产品实现，OctoScript 中的模型调用、多源读取和路线任务均未接通。初赛截止为 2026-10-04 23:59（北京时间）。

## 目标与授权

演示输入仍为：“40 分钟内到机场，预算 50，尽量便宜。”系统需要从有来源的上下文补全机场、币种和出发位置，再比较公共交通、打车及混合方案。限定时间内尽量省钱的产品目标不变。

用户本轮明确：“撤回一下我们前面的边界，关于不能我们自己接入地图、打车、天气、日常这些服务。在初测阶段，我们还是选择先直接接入这些服务，做一个老老实实的 navigation agent，但是要利用比赛官方给的这些工具链去搭建。”

用户随后明确：“不用这么着急，你继续做方案、计划；演示用深圳；你需要什么地图、服务，我就去找，去给你提供”。因此本轮范围是调查、方案与任务包维护，不开始应用实现、宿主升级或服务接入，也不要求用户现在准备账户。

用户同意方案后修正：“如果要 mock/demo，也应该至少是日历文件 + 笔记 + xxx，而不是整合为一个所谓的行程背景文件”；指定“应用的 LLM 使用 minimax m3”，并补充“初赛代码只要求 octoscript 的应用”。这些决定替换此前单一背景文件、模型待选和默认新增宿主服务的计划，当前没有另行开始产品实现的指示。

用户随后要求：“创建一个 .env 文件吧，高德地图、minimax等的配置我都会放里面”，并告知“我配置好了”。在已有隔离实验与服务核对范围内，本轮读取配置并做最小真实请求，不输出密钥、不写入应用包；未修改产品源码或升级宿主。

此前禁止服务 API、必须操作手机既有应用的边界撤回，手机型号和既有应用组合不再是前置条件。服务清单由本项目提出，用户后续准备；实际接入需具备相应配置与授权，凭据由宿主或服务端管理。此前“你可以自由提交”仍适用；推送、发布及赛事提交需要对应授权。

## 首轮范围与验收建议

首轮使用一个地图提供方覆盖公共交通与出租车估价，背景则保留日历、笔记和位置三个独立来源，由 Agent 在运行时关联。初赛交付以 OctoScript 应用为边界，优先复用现成宿主接口，不预设新增 Rust 服务或独立后端。天气、提醒、手机自动化、运行时动态生成工具、长期偏好学习及多城市泛化不作为首轮前置。本地表单仍只是开发调试工具。

1. 收到指令即确定绝对到达期限为接收时间加 40 分钟；上下文读取、查询和确认的耗时均计入。
2. MiniMax M3 通过应用工具分别查询日历、笔记与位置，关联事件日期、机票信息和记录时效，补全机场／航站楼和币种并显示依据。上下文充足的正常场景不要求用户补填；证据冲突只追问关键项。不能提前合并为任务答案再交给模型复述。
3. Agent 组织真实服务查询，取得全公共交通、全打车及至少一条合理混合候选。确定性代码核对路段衔接、等待／换乘、时限与预算，Agent 解释结果。
4. 显示已核实候选中估价最低的可行方案、来源和查询时间。缺价不记为零；估价区间跨过预算或时段不适用时不能标成满足约束。有限候选不宣称全局最优。
5. 用户确认后建立包含所选路线、约束和来源的 Trip，再读回确认状态。已验证导航交接接口时，再进入与所选方案匹配的路线并核验；建立 Trip 不等于已经开始导航或实际到达。

初赛至少覆盖一次完整成功操作和一个失败／空状态。日历保留合理的无关事件，笔记保留独立记录与更新时间；更改单个来源后重跑，验证选择、约束或澄清随之变化。无法消解的有效记录冲突应只追问关键项。演示起点与时间在服务实测后选择，不预设 40 分钟／50 元内必有混合方案，更不能修改返回值制造优势。明确标注的模拟来源不能冒充真实账户接入；在线交通结果与测试数据分别记录。

Agentic 演示需保留运行时的决策依据：例如公共交通超时、全程打车超预算后，Agent 根据工具结果补查有希望满足约束的接续路线；来源冲突时转为澄清，没有候选时报告不可行。路线计算仍由确定性代码完成。工具调用记录应能解释为什么继续查询或停止，而不只是展示一次自然语言解析和固定答案。

### 自动补全的依据

| 缺失项 | 补全与检查 |
| --- | --- |
| 机场与航站楼 | 读取与本次出行相关的有效行程或日程，核对日期、出发／到达机场及航站楼。最近机场不能单独证明目的地；来源冲突时澄清。 |
| 出发位置 | 使用获授权的当前定位或本次任务已有的明确出发点，检查时间和适用范围。 |
| 预算币种 | 优先遵循已有明确偏好；否则结合本次出行服务的报价币种与地域上下文推断并明示。语言或有歧义的货币符号不能单独决定币种；来源冲突时澄清，不把不同币种直接相加或比较。 |
| 到达期限 | 从接收指令时起算 40 分钟，不能在查询结束后重置；“到机场”不被替换为保证赶上航班。 |

## 官方工具链的职责与已查证接口

官方课程将 octos 定义为运行时 Agent 内核，OctoScript／Makepad 承载界面和交互，Rinx／OctoSense 提供宿主；octoscode 和 OctoLoop 用于开发协作及审查，不因参与写代码就证明作品有运行时 Agent。无需为了工具数量而接齐全部项目，来源归[资料核对](../../docs/sources.md)。

当前[锁定工具链](../../toolchain/sources.lock.json)只跑通了 macOS arm64 card-host；[本地开发任务](../local-development/packet.md)保留实际验证。它没有 host services，不能只改 manifest 就宣称模型和工具已接通。本机 PATH 尚未发现 octos 或 octoscode 二进制。

本轮在 GitHub 核对了 OctoSense 提交 d405d5ca53012cb6bf606ed9323c68baf12c7ec6，其 Cargo.toml 配套锁定 octos ae230ce04d57f3c29cf6c2518e5956a86c07d788 和 App Hub 58c3c8aed8fc811a16d67c5f784a8a44214ff876。以下是源码证据，不是本项目运行结果：

- crates/ai-host/src/lib.rs 注册 model 与 octos 服务；shipped 策略默认在用户同意后启用 contained app，不能照搬旧文档中“所有宿主均不可用”或“默认关闭”的描述。
- contained.rs 可准备应用自己的 peer；crates/shell/src/host_tools/script_apps.rs 从通过准入检查的 bundle 读取 tools.json，将 implemented_by 为 host-service 的调用交给对应服务，再回传结果。
- News 已有 news.list 与 news.read 的声明示例。若采用该集成路径，Navigation 的服务、权限和宿主注册仍需实现；仅添加工具声明不构成集成。implemented_by 为 app 的执行路径尚不可用，不影响应用自行调用脚本函数。
- model.complete 是一次性结构化模型调用，只接受 task、input、schema、class、allow_urls，不接受原生 tools 或消息历史。它按宿主配置选择提供方和模型，不能由应用直接指定 M3。应用可以据此实现经校验的下一步动作循环，尚待实测。

初赛先验证现成模型接口与 OctoScript 应用侧循环；已有 octos 应用 peer 和原生工具服务路线保留为后续候选，不再是硬前置。只有实际缺少必要能力或凭据通道时，才评估最小补充。新版本目前仅用于调查，没有替换锁文件、修改上游检出或构建新宿主；如使用新宿主，仍需遵循其兼容版本组合。

## 服务预检证据

2026-10-01 20:42–20:43（北京时间），通过本机 Python 与 curl 脚本做了两次 M3 请求和五次高德请求。只使用公共地点和随机探针值，没有读取用户日历、笔记或实际位置。脚本及筛选后的响应保存在忽略目录 `build/research/service-preflight/`；以下是可保留的观察结果，不等于官方宿主集成证据。

| 检查 | 实际结果 |
| --- | --- |
| 配置 | 四个配置项均存在，模型值为 MiniMax-M3，Base URL 为国内平台 HTTPS 地址；未输出密钥。 |
| M3 工具循环 | 两次 HTTP 200，响应模型均为 MiniMax-M3。第一次返回 read_probe 工具调用；执行器产生新的随机标记，第二次模型准确返回工具结果中的标记。使用非思考模式和每次最多 256 输出 token，证明服务侧原生工具往返可用。 |
| 深圳地点 | `/v3/place/text` 分别查询市民中心及机场 T3，均返回 status=1、infocode=10000；终点选中 T3 国内出发点，未使用停车场条目。 |

## 实施顺序与完成依据

以下是后续开工计划；当前只完成方案、接口调查和服务侧预检。每步都用结果决定下一步，避免先铺开所有服务。

| 阶段 | 工作与通过条件 |
| --- | --- |
| 1. OctoScript 与 M3 | 在拟交付的官方宿主中验证最小应用循环：M3 选择读取日历、笔记或位置，OctoScript 执行并回传独立来源结果，M3 据此继续。优先检查现成 model.complete 的结构化动作方式；若采用原生 Function Call 通道，须验证完整消息及工具结果传递。确认实际模型是 M3、凭据不会进入 bundle；窗口启动或单次文本回复不足以通过。只有证实必需能力缺口后才讨论增加宿主改动。 |
| 2. 深圳数据可用性 | 用高德真实接口检查一组起终点的地点、公交票价、时刻、步行、驾车时间和出租车估价，确认字段、坐标系、币种与查询时段。优先复用服务完整候选；混合候选不足时，仅从实际公交线路中选少量换乘点，查询完整接续路段。用真实数据判断哪些起点适合演示，保留无可行方案的结果。 |
| 3. 一句话任务 | M3 关联多源记录、形成结构化约束、按工具返回补充查询，确定性代码比较候选。先展示所补全内容及来源，再解释推荐与价格／时间差异；确认前重检剩余时间，确认后保存并读回 Trip。成功证据需包含全公共交通、全打车和至少一条合理混合候选的比较，不能只复述自然语言。 |
| 4. 复现与交付 | 检查机场来源冲突、费用未知、无可行路线和数据过期；仅更改笔记或日历后重跑，确认行为相应变化。交付 OctoScript 应用与真实宿主版本、启动说明；记录在线与模拟数据边界、实际截图和成功及失败／空状态视频。导航交接如加入，单独验证。 |

模型账户和所测地图接口权限已通过预检。首个工程风险仍是 OctoScript 经现成通道调用指定 M3 并完成工具循环；业务上需继续核对混合总价、候车与到达时限，不能把某一响应成功当作完整路线可行性验证。两项未通过前，不扩展天气、偏好学习或动态工具生成。10 月 4 日应预留为复现与交付时间，不把主要集成留到截止前。
