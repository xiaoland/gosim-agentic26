## 首轮范围与验收建议

首轮使用一个地图提供方覆盖公共交通与出租车估价，背景则保留日历、笔记和位置三个独立来源，由 Agent 在运行时关联。初赛交付以 OctoScript 应用为边界，优先复用现成宿主接口，不预设新增 Rust 服务或独立后端。天气、提醒、手机自动化、运行时动态生成工具、长期偏好学习及多城市泛化不作为首轮前置。当前入口已替换为一句话任务与确认界面。

1. 收到指令即确定绝对到达期限为接收时间加 40 分钟；上下文读取、查询和确认的耗时均计入。
2. MiniMax M3 通过应用工具分别查询日历、笔记与位置，关联事件日期、机票信息和记录时效，补全机场／航站楼和币种并显示依据。上下文充足的正常场景不要求用户补填；证据冲突只追问关键项。不能提前合并为任务答案再交给模型复述。
3. Agent 组织真实服务查询，取得全公共交通、全打车及至少一条合理混合候选。确定性代码核对路段衔接、等待／换乘、时限与预算，Agent 解释结果。
4. 显示已核实候选中估价最低的可行方案、来源和查询时间。缺价不记为零；估价区间跨过预算或时段不适用时不能标成满足约束。有限候选不宣称全局最优。
5. 用户确认后建立包含所选路线、约束和来源的 Trip，再读回确认状态。已验证导航交接接口时，再进入与所选方案匹配的路线并核验；建立 Trip 不等于已经开始导航或实际到达。

初赛至少覆盖一次完整成功操作和一个失败／空状态。日历保留合理的无关事件，笔记保留独立记录与更新时间；更改单个来源后重跑，验证选择、约束或澄清随之变化。无法消解的有效记录冲突应只追问关键项。演示起点与时间在服务实测后选择，不预设 40 分钟／50 元内必有混合方案，更不能修改返回值制造优势。明确标注的模拟来源不能冒充真实账户接入；在线交通结果与测试数据分别记录。

Agentic 演示需保留运行时的决策依据：例如公共交通超时、全程打车超预算后，Agent 根据工具结果补查有希望满足约束的接续路线；来源冲突时转为澄清，没有候选时报告不可行。路线计算仍由确定性代码完成。工具调用记录应能解释为什么继续查询或停止，而不只是展示一次自然语言解析和固定答案。

## 官方工具链的职责与已查证接口

官方课程将 octos 定义为运行时 Agent 内核，OctoScript／Makepad 承载界面和交互，Rinx／OctoSense 提供宿主；octoscode 和 OctoLoop 用于开发协作及审查，不因参与写代码就证明作品有运行时 Agent。无需为了工具数量而接齐全部项目，来源归[资料核对](../../docs/sources.md)。

原[锁定工具链](../../toolchain/sources.lock.json)只跑通了 macOS arm64 card-host；[本地开发任务](../local-development/packet.md)保留实际验证。它没有 host services，不能只改 manifest 就宣称模型和工具已接通。本机 PATH 尚未发现 octos 或 octoscode 二进制。

本轮在 GitHub 核对了 OctoSense 提交 d405d5ca53012cb6bf606ed9323c68baf12c7ec6，其 Cargo.toml 配套锁定 octos ae230ce04d57f3c29cf6c2518e5956a86c07d788 和 App Hub 58c3c8aed8fc811a16d67c5f784a8a44214ff876。以下列出源码接口；本项目的运行结果另见下方集成证据：

- crates/ai-host/src/lib.rs 注册 model 与 octos 服务；shipped 策略默认在用户同意后启用 contained app，不能照搬旧文档中“所有宿主均不可用”或“默认关闭”的描述。
- contained.rs 可准备应用自己的 peer；crates/shell/src/host_tools/script_apps.rs 从通过准入检查的 bundle 读取 tools.json，将 implemented_by 为 host-service 的调用交给对应服务，再回传结果。
- News 已有 news.list 与 news.read 的声明示例。若采用该集成路径，Navigation 的服务、权限和宿主注册仍需实现；仅添加工具声明不构成集成。implemented_by 为 app 的执行路径尚不可用，不影响应用自行调用脚本函数。
- model.complete 是一次性结构化模型调用，只接受 task、input、schema、class、allow_urls，不接受原生 tools 或消息历史。它按宿主配置选择提供方和模型，不能由应用直接指定 M3。应用可以据此实现经校验的下一步动作循环，已在下述宿主探针中实测。

初赛先验证现成模型接口与 OctoScript 应用侧循环；已有 octos 应用 peer 和原生工具服务路线保留为后续候选，不再是硬前置。只有实际缺少必要能力或凭据通道时，才评估最小补充。该兼容组合现已由独立 agent-runtime.lock.json 固定并构建，保留原 card-host 工具链；没有修改上游 Rust 源码。

### 集成验收约定

真实请求与可重复的边界测试分开取证。真实宿主成功路径必须经过应用交互、M3 的多次动作选择、独立来源读取、在线交通结果及 Trip 写入读回；模型或网络不可用时必须结束为可见错误，不能改用固定答案冒充完成。隔离数据测试则覆盖以下行为，不反复消耗在线接口来验证纯函数。

| 情形 | 需要观察的结果 |
| --- | --- |
| 三份独立背景与无关日程 | 工具记录包含各来源的独立读取，约束引用相关记录；不会直接取第一条日程。 |
| 只修改一份笔记或日历 | 关联的机场／航站楼随有效证据改变；有效来源互相冲突时澄清。 |
| 位置过期、缺失字段、工具错误 | 缺失保持缺失，用户看到具体阻塞；不编造坐标、价格或成功结果。 |
| 混合费用、未知价格、超时与超预算 | 使用完整候选总价，不重复加出租车段；确定性代码排除未知或违反约束的候选。 |
| 查询耗时与确认延迟 | 使用首次收到指令的期限，确认前按当前时间再校验；不能重新给 40 分钟。 |
| 非法模型动作、重复动作或迟到回调 | 拒绝未授权动作，循环有次数与时间上限；旧任务回调不能覆盖新任务。 |
| 确认、持久化与重启 | 保存所选路线、约束和来源；读回一致才展示已确认，失败保留用户可恢复状态。 |

应用入口保持一句自然语言，来源、进度、候选差异与确认结果都可查看。交互测试已按新入口调整；离线合成响应和包预检仍与真实任务分开验收。
