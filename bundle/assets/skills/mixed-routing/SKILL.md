# 寻找有价值的接驳

优化用户的到达期限、预算和偏好，接驳次数与工具调用数不是目标。保留有价值的公共交通主干，主动寻找能改变推荐的局部替代；普通导航返回的整程方案是探索材料，不是搜索边界。工具的Route与计价事实见navigation-data。

从已有分段、线路与真实站点寻找瓶颈：长步行或慢公交接入可能值得更早接上主干；末段绕行可能值得提前离开主干；中段长绕行或换乘负担可能值得跨站连接。也可搜索整程方案之外的真实站点。这些是形成假设的例子，不是每轮必查清单。缺少分段或节点关系时，get_route/get_route_graph可以补足；不得凭空猜坐标、站间耗时或费用。

让每次探索检验具体假设，例如“打车接上这条地铁主干，是否能消除首段慢公交，并比全程打车更便宜”。预算上限只判断能否负担，不代表“尽量便宜”的目标已经完成。直达公交超期不证明局部公交＋打车也超期；已有预算内全程打车时，仍应对照已知慢接入与有价值的主干，检验可能更便宜且满足期限的替代，或用真实分段事实说明为什么不值得。候车未知不意味着各段都无比较价值，但不能抹去未知而宣称成立。

现有工具只能前向扩展：origin种子到真实中间节点，再从返回Route的实际末端延长。替换首段要从origin重新建立到主干接入点的前缀；从整程方案的终点继续延长，只能探索末段连接，不能替换已经走过的慢接入。要改原公交前、中、后段，需重新查询各完整供应商区间，不能把原方案截成可收费片段。前序抵达时刻由工具传给后续查询；原方案内部站点的顺序用于挑选假设，不证明新组合已衔接。详细例子见[接驳假设](references/hypotheses.md)。

是否继续取决于分段瓶颈、连接缺口与价格证据能否改变推荐，而非已有方案是否落在预算内。结束探索时说明已检验的替代，或依据哪些真实事实判断剩余机会不值得或无法检验；没有查询的接驳不当作已否定。相同端点/方式在资料或时间变化后可能需要重查，重复查询本身不是改进。找不到优势、真实服务失败及证据不足也是有效结果；交付已查范围和未知，不声称穷尽或全局最优。
