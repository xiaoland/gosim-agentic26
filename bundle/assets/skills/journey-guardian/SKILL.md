# 已确认目标的核验与替代

普通新输入建立独立出行；守护核验维护facts.guardian的已确认目标，不放宽目的地、绝对到达期限、总预算/币种或用户确认的偏好风险。已花费用从总预算扣除；进度和费用只能由父应用真实用户确认，位置不证明乘车或付费。

重新打开只展示带时间的历史详情，主动核验才建立新工具循环。saved_goal_route是已确认路线的历史快照，original_route_id仅溯源，旧报价/耗时不能认证本轮成立。current_check是本轮判定，last_check是上次核验。

report_goal_check用本轮新Route计算并记录valid/invalid/unknown；省略route_id可检查已过期、已超支或信息不足。本工具结果才是本轮原计划判断，不能口头用旧数据自算成立。已知超限为失效，缺交通/费用/候车/连接依据为未知；新线路只是替代候选。不能把unknown改写为符合，也不能把passed=false解释成每项都超限。

original_plan_reexecution以当前时刻重走原整程，固定班次不向后平移；它保留旧source_ts，不是新交通查询，也不由位置推断已登乘。起点不匹配、有已确认进度或费用时，剩余行程仍未知；即使重走整程已错过班次，也不要把在途实际状态改写为已错过。费用比较的full_journey_delta_cents仅在两方案整程费用可比较时提供；queried_legs_subtotal_delta_cents是已查路段小计差，覆盖范围可能不同且旧报价未刷新。

约束失效时主动探索替代；证据不足时也可寻找有价值的接驳并说明未取得的依据，策略见mixed-routing。展示差额、来源与风险，进度存在时完整旧路线价格不等于剩余价格，不重复计算已付票价。

提案assessment与Route使用同一到达范围：目的地证据未覆盖时estimated_arrival_ts为nil，queried_endpoint_arrival_ts仅是已查终点；duration标签标明已查最早场景。父确认显示权威费用／到达范围与状态，selection_basis是Agent推荐理由，不是可行性认证；推荐理由不能把unknown升级为成立，unknown提案仍可由用户了解风险后确认。

propose_goal准备本轮真实Route及待用户确认的偏好／风险文字，无需用户此前确认；它只暂存提案，不保存或替换目标。用户点击父应用确认才保存或替换，不能先要求用户确认一个尚未准备的提案。用户确认不会升级路线可行性，保存失败不生效。历史界面恢复不恢复提案或模型执行。只有前台主动核验，不后台监听或下单。

费用的queried_legs_amount_cents／queried_legs_complete说明已查腿报价合计，queried_legs_scope、queried_leg_count和unknown_reasons解释覆盖终点及未核接入；即使全部已查腿有价，到官方入口的估价仍可能遗漏未核连接附加费用。destination_access说明内部通达未知，不表示一定收费。可以推荐条件成立／unknown方案，但不能把它称为已满足预算或期限；不要将别条Route或未选班次的票价拼入旧Route来认证总价。新提案风险文字不是用户已接受，不能覆盖原用户risk_acceptance。
