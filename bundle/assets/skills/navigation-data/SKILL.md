# 地点与路线事实

read_location按配置读取设备或明确模拟位置并核实城市。仅demo提供read_calendar/read_notes/set_constraints；它们是模拟日历和机票笔记，不是真实个人资料。约束依据保留记录ID和逐字citations；保留用户给定的分钟数与预算；金额单位为整数分。search_places返回真实POI与node_ref，不采用目标；adopt_destination采用已有poi_id并保留明确选择或推断依据，不伪造航站楼。

query_route从本次起点查询，省略to_ref到最终目的地，指定真实中转node_ref则只建立到该节点的新前缀；transit策略由参数说明，taxi为高德单路径驾车估价，候车未知。extend_route从origin或本轮Route实际末端到真实node_ref查询完整新段，返回新Route，原Route不变。Route id用于读取、比较、提案与查看，geometry_ref用于真实地图几何；模型不传polyline或手算重建路线。

一个leg是一笔完整供应商查询，公交内部steps不是独立收费边，不能按站数/距离拆票价或替换其内部taxi step价格。短steps包含真实分段duration/distance、walking/taxi及每条busline的line_id、上下站node_ref；供应商缺失字段为nil，不推算站间耗时。get_route按线路分别提供有序stops及route内leg/segment关系；get_route_graph提供节点的多线路归属，同站属于多条候选不会覆盖。替代buslines各有自己的站序，不把它们拼成一条线路。stop缺有效ID/坐标时node_ref仍为nil。

cost.amount_cents是所包含legs估价合计，任一leg缺价则nil；known_subtotal_cents仅已知小计。full_journey_amount_cents仅在起终点与连接核实、金额齐全时提供，否则nil。coverage=queried_legs_only的小计不是到目的地总价；unknown不是零。费用为整数分且保留currency、basis与来源。

completion_status区分reached_requested_destination/incomplete/unknown，实际末端不等于请求坐标。代码检查实际端点连接并累计时间；公交按前序最早抵达场景查询，前序未知候车可能改变班次。未来打车仍使用查询当时交通估计。get_route提供estimated_arrival_ts与waiting_slack_seconds，余量不是已知候车时间。

新规划期限从received_at起算，查询和生成时间计入；守护使用已确认绝对期限。assessment由当前时刻重算：预算、截止、连接、候车和时效各自判断。passed=false不等于每项超限；数值在范围内不能认证未知连接/候车。来源expires_at与到达截止不同。get_route/get_route_graph/compare_routes只读已有资料，不重新查询供应商；已查范围不证明全局最优。

滴滴配置事实只表示Key是否配置，不等于服务可用。search_didi_places返回供应商地点ref，quote_didi只用该ref询价；优惠不默认适用，不能精确解析的金额为nil。attach_quote只替换明确taxi leg的当前报价并返回新Route，不与原价叠加。place_basis保留两端名称、城市、地址及入口对应依据；供应商坐标系未声明，不能冒充高德端点。派生保留原耗时/几何/完成状态，不认证上下车连接；当前价不保证未来接驳价格。

探索策略见mixed-routing；已确认目标规则见journey-guardian；呈现、事件和地图接口见native-ui。普通结果保存为带时间的历史资料，不恢复模型会话，也不自动续跑。
