# agentic26 · Navigation

GOSIM Agentic App 2026 参赛开发仓库，主场景为 Navigation，实现方向为**帝王蟹能力层**。

## 产品目标

在限定时间内组合步行、公交、地铁和打车，以最低费用抵达目的地，包含混合路线中的打车计费。长期目标是通过已授权的跨应用上下文和偏好减少用户表达；当前阶段只做独立查询，不建立长期记忆或对话澄清。日历、消息、机票邮件或设备状态是候选数据源，具体接入尚待确定。

初赛以 OctoScript 应用交付，复用比赛官方宿主，应用模型指定为 MiniMax M3（`MiniMax-M3`）。Agent 通过工具读取背景、查询交通并决定下一步，确定性代码检查候选路线，应用呈现方案和任务结果。模型与交通循环复用现成网络接口；用户另行批准补齐 macOS 实时定位的宿主链路，参赛应用仍以 OctoScript 交付。本项目继续以可被调用的出行能力为重点，自然语言入口与可纠正的目的地、候选方案视图是当前开发入口。

直接服务接入已获用户允许，不再要求所有数据与操作经过手机既有应用。首轮先接任务必需的服务；天气、提醒、手机自动化和运行时动态生成工具不作为前置，避免扩展到完整出行服务平台。

当前路线规划不按演示城市限制起终点，输入是一句“40 分钟内到机场，预算 50，尽量便宜。”系统需要从已授权、有来源的行程、位置和偏好补全机场、币种和出发位置。没有可靠行程时，Agent 查询机场候选并提出可纠正的目的地假设；真实位置不能将模拟机票变成用户的真实行程。早期版本曾验证行程确认与恢复，但这些行为在当前无持久化方向中撤除；对应历史证据归[能力任务](tasks/capability-boundary/packet.md)。

结果目标包括让用户查看已评估方案的分段、费用、用时及限制，并在所选方案详情中提供实际地图；没有可行方案时，仍展示各方案未满足条件的具体原因。Agent自行决定如何组织这些内容与详情入口。0.11.5将这一目标补入现有元提示，尚未通过新一轮真实模型查询验证，不作为每次都会生成完整详情的保证。

演示背景也按实际来源分别提供：日历文件、笔记和设备位置记录。Agent 在运行时关联这些资料，形成带依据的出行约束；不预先把目的地、偏好和起点整理为一个“行程背景文件”。演示数据与真实在线服务结果分别标注。应用已接入一次性设备定位请求，默认使用真实设备位置，模拟位置保留为显式演示模式；系统调用的实际结果与完成证据见任务包。

后续考虑疲劳、最快等目标，比较时间、换乘和可靠性的候选方案。持续行程、交通变化时重规划和长期偏好学习均为后续方向，不属于当前独立查询。“最慢”的含义尚未确定；“最晚出发”是候选解释。

## 当前能力

0.11.6支持命名DSL区块：render_ui可一次提交一个或多个区块，追加或仅替换指定区块；每块仍由Agent编写Makepad／Splash。普通区块使用连续滚动，详情可用独立覆盖层，保留列表状态。旧source调用保持整页替换语义；不将总结论、解释、卡片、建议与详情固定成宿主五个模板。macOS宿主Android模式验证了增量状态、跨块详情与单块诊断；随后补查详情滚到底时的裁剪和固定输入／查询可见性。没有新增真实模型或出行服务请求，不据此保证Agent每次生成完整方案。接口及证据归[区块任务](tasks/ui-blocks/packet.md)。

0.11.4修复首次生成界面时重新扫描全部路线几何造成的挂起。地图目录改为 `get_route` 按需计算并复用，UI快照只读取已取得的目录；`map_paths` 未读取时为nil，不等于没有几何。普通地图仍可直接加载完整路线。工具结果先提交标准消息并安排续轮，再独立更新日志和UI，结束／取消先清运行状态；保留同一function-calling loop，不增加固定流程或模型轮次上限。根因与Pi源码对照归[性能任务](tasks/agent-performance/packet.md)。

同源码Android模式挂起边界七项与分图七项检查通过：16候选首次挂载不扫描几何，657点已存真实路线按需冷读／缓存复用，UI／日志故障不阻断已提交的工具结果续轮，结束／取消清运行状态。当前未新增真实M3查询，不将此前十次生成界面修稿的质量问题宣称为已解决；更大单路线负载也不在该证据覆盖范围内。

0.11.3向Agent说明高德静态图每张最多四条独立折线，并提供路线的全部折线索引目录和可选 `path_indices` 地图事件。Agent可以将同一路线分步放入多张地图，每张按所选完整折线取景；应用不自动分组、不截断几何或跨缺口补线，费用与可行性仍针对整条路线。系统提示和自由生成界面的边界不变；实现及验收入口归[性能与地图诊断任务](tasks/agent-performance/packet.md)。

分图检查还发现并修复同批本地事件的异步读改写覆盖。macOS宿主Android模式七项定向检查通过，使用六条合成折线和两张合成图片验证完整分段、独立相机及旧调用兼容；没有新增M3或地图服务样本，不据此保证Agent每次采用分图或完整界面已经通过验收。

0.11.2整理模型与界面的数据传递：工具返回本次取得的候选、节点和具体计算结论，完整路线／图可按需读取，不再每次附完整界面状态。原生snapshot仍提供所有候选、分段、报价和图资料；状态未变化时跳过序列化与跨界面复制。新查询清空上轮地点与预览，工具记录不重复保留完整结果对象。该修复针对真实日志中的输入膨胀、旧地点误选和临时堆分配压力，耗时改善须以实际证据为准；入口归[性能任务](tasks/agent-performance/packet.md)。

同组合成记录的模型输入字节减少85.24%，12项隔离回归通过。一次真实M3查询耗时约56秒，首次生成执行成功且未观察到堆／预算错误，但页面仍有文字重叠和失效详情按钮，完整界面尚未通过验收。该样本使用演示地点与独立日历／笔记、真实出行服务及macOS宿主Android模式，不作为真机验证或公平前后速度对照。

0.11.1修复开发记录文件数配额与迟到渲染通知：诊断改用分段追加，旧开发记录在下次启动停止原实例后迁出保存；同稿通知迟于工具回执或终端文字时，仍依据实际诊断更新显示。这两处针对已查明的问题，不证明Agent每次都会生成完整地图与详情；验证入口归[查询交付任务](tasks/query-delivery/packet.md)。

0.11.0加入主动逐段混合与滴滴正式询价。Agent可以选择本轮真实POI／公交站，将步行、出租车、公共交通完整区间继续连接；代码按前缀到站时刻查询、累计费用与时间，并保留未知衔接。高德出租车改用单路径估价，修正多路径结果主动丢价造成的“费用未知”。滴滴工具可搜索真实地点、查询多车型当前价格，再将所选报价替换指定打车段估价并重算组合费用；优惠单列，坐标／上下车对应仍是假设，不因为报价存在就保证换乘或准时。

正式滴滴已在macOS宿主Android模式取得七车型报价；10项确定性原生检查覆盖混合计价、断段、预算期限及报价替换。真实高德工具链取得打车→公共交通→步行、已查部分23元，但超40分钟且末端未连接机场POI，没有完整到达候选。它是可解释的探索尝试，不能称可行方案；本轮没有新增M3自主规划验收，不承诺Agent每次都会充分探索或现实全局最优。事实、源码与证据边界见[混合路线任务](tasks/mixed-routing/packet.md)。

0.9.0 接入AutoNaviMapView原生交互地图与详情切换示例；继续按无持久化、无澄清的单次查询运行。每次点击查询建立新任务，位置、约束、来源、候选和 Agent 工具历史只服务本次运行；不保存或恢复行程，不把新输入当上一轮补充，也不通过问题澄清等待用户回答。未知信息应形成有依据的假设、具体缺失或查询失败结果，不能伪造机场、航站楼或价格。

用户实际0.9.0查询发现首次授权后定位失败、有结果无地图、仅“查询完成”无内容、以及仅摘要无详情。0.9.1分开系统授权等待与定位采样，显示模型终端文字，修正Android首次生成区域零高度和刷新丢稿，以及请求失败误报渲染错误。Android合成模型的5项原生检查通过，真实首次系统授权未重测。此前真实地图联调只验证原语和直接挂载的示例，早期正常M3样本暴露生成事件API错误、结论误读及预算错误。最终原句样本在macOS宿主Android模式、显式模拟位置下，由真实M3和高德完成候选列表、两条候选地图／费用／限制详情与返回，点击不追加模型请求；仍缺逐段道路和公交详情，不能称完整规划或普遍可靠。预算错误未精确复现，保留该不确定性。修复与现场证据见[查询交付任务](tasks/query-delivery/packet.md)。

0.9.2统一结果展示：正常生成界面时隐藏宿主最终纯文本；无可用生成稿时以最终文字兜底，失败稿隐藏而不销毁。回复保留在本次历史和事实，不并列输出两份结果。Android定向6项检查通过，未新增M3或出行服务请求。

0.10.0加入开发态诊断：实际模型正文、派发与响应、工具调用、生成源码、原生渲染和本地地图事件按实例／查询关联，导出附同启动器宿主日志。Android 7项定向检查与导出包装器检查通过；一次真实M3回复已完整记录，但任务随后在read_location入口触发宿主执行预算中止，未完成路线或渲染。相同工具的开关记录对照均完成，现场预算错误原因仍未确定；地图省略问题尚未证明解决。

0.9.3修正成功稿被后续局部错误隐藏的展示缺陷，并澄清viewport是可见范围而非内容高度上限。Android定向7项检查通过。用户本次无地图现场实际是Agent以视口小为由省略地图控件与请求，未证明这些局部修正能解决该生成决策；尚未加入宿主保底地图。

路线查看是生成稿的本地交互：选择父状态后，稿自身须显示对应分段、费用与限制，不会自动出现宿主预制卡片。当前技能用普通View的可见性切换展示独立详情页与返回，保留列表控件；Agent仍自行决定布局，无预制路线详情组件。Android模式合成路线检查确认长详情到底、返回列表位置与编辑内容保持、隐藏列表不响应点击。使用显式返回按钮，未接系统返回手势，未新增M3抽样证明未来稿都采用页面。0.8.1曾修正技能中只有选择事件的误导示例；一次定向M3修稿在Android模式实际显示两条路线各自的费用、限制和公交分段，点击不调用模型。实验以代码块返回并直接挂载，不等于正常规划harness自动交付验证；旧已生成页面需重新查询。原始渲染诊断继续回给Agent，修正中的用户反馈简短，成功后清除。用户报告的empty stack本次未复现，根因仍未确认。

路线详情的呈现目标包含所选路线地图、分段、费用与限制；技能示例使用AutoNaviMapView和本地map事件，Agent仍可自行组织界面。控件支持单指拖动、双击／按钮缩放，以及全路线取景；拖动或缩放改变相机后，通过高德官方静态图接口加载对应新区域，并非只放大原图片。同一路线返回保留相机，换路线重新取景。底图刷新有网络延迟，不是无缝瓦片地图，尚未支持双指捏合。

macOS宿主Android模式的真实高德图联调已确认：拖动220像素的标记位置与刷新图一致、新区域出现、缩放获得新细节、两路线图不同、地图外详情滚动正常、返回保留列表位置及同目标相机。使用公开演示端点与实际几何，不是GPS或本轮M3自主规划；本轮模型请求0次。原生相机／旧请求检查及四项定向原生回归通过，完整证据归[交互地图任务](tasks/interactive-map/packet.md)。控件属于锁定宿主覆盖，原生官方MapView的中国底图未直接采用；普通Image行为与其它应用主题保持原样。

几何只在共享端点无损合并，不跨缺口，更多不连续路径可能触及高德接口能力，将显示实际错误，不截断路线。HTTP200错误JSON不标为图片成功；视口刷新期间的旧帧是预览，失败不等于新视口已加载。旧Image接口仍可显示静态图。

AppCard完整助手当前未启用。锁定源码调查发现它依赖Octos kernel，客户端缺少现有业务工具的结果回传；本轮保留已运行的HTTP工具循环，不搬入助手的检查器或纠正预算。复用评估及后续判别条件见[架构说明](docs/architecture.md#appcard复用评估)，不把模型配置存在当作接入运行成功。

业务和展示由同一个 MiniMax M3 Agent 自主编排。应用提供定位、地点、交通、确定性比较、按需技能和原生渲染工具；固定外壳仅输入框和查询／终止按钮，其余内容由 Agent 生成 Splash／Makepad。没有预制分区、组件树白名单、地图数量或人为输出限制。原生布局资料解释内容自然高度与文字换行，生成区承载手机视口中的滚动；不规定页面组织。

正常模式从宿主取得真实位置，日历和笔记账户尚未接入，不提供演示文件作为用户背景。显式 demo 模式保留分别提供的日历、笔记和位置来源，不能伪装成真实个人数据。地图与交通使用在线高德服务；确定性代码计算已查询候选的费用、耗时和未满足条件，费用未知不等于零，不可确认现实全局最优或实际到达保证。来源资料、运行配置和技能材料不是用户查询结果，不受行程保存机制管理。

0.8.0的9项针对性原生检查通过，覆盖每次独立会话、旧结果文件不读不写、终止迟到响应、再次查询的新时间和预算、Android长文字换行及滚动到末行。真实live查询中定位超时，M3取得实际机场候选并根据执行诊断修正生成稿，未形成路线；随后复用这份真实稿在修复后布局确认末尾可达，不把它称为重新完成在线规划。真实稿仍含内部字段与过时“正在处理”标题；已补简短用户输出目标，但没有新增模型抽样证明内容质量已可靠。当前剩余局限、源码差异和完整证据归[动态界面任务包](tasks/agent-generated-ui/packet.md)，用户验收仍待进行。

0.7.0曾用模拟起点和真实服务完成自主查询与生成按钮交互，但存在文案误判和裁切；旧版本的Trip确认、读回与恢复记录只证明历史行为，当前不再提供这些入口。

Navigation 单独使用中文无衬线字体，其它应用文楷主题保持原样。当前验证目标为 macOS arm64 宿主 Android 手机模式，未验证 Android 真机。尚未接通真实日历／笔记账户、导航执行、持续监测或长期偏好学习。地图使用供应商同源几何，缺段不补造直线；历史 Maps 选点往返使用锁定的宿主扩展，本轮单次查询不提供该交互，也不申请 maps 能力。

开发指引见 [AGENTS.md](AGENTS.md)，知识归属见 [文档导航](docs/index.md)。仅采用 SVC 的文档知识层与 task packet，它们不是应用记忆能力。

## 开始开发

macOS Apple Silicon 是当前验证目标，需要 Git、Rust stable、Python 3.9+ 和可用图形会话。依赖源码放在仓库同级的忽略目录，不进入参赛包；首次编译需要网络与数 GB 磁盘空间。

在 Git 忽略的 `.env` 配置 `AMAP_API_KEY`、`MINIMAX_API_KEY`、`MINIMAX_BASE_URL` 和 `MINIMAX_MODEL=MiniMax-M3`。高德使用 Web 服务 Key，当前模型地址固定为 `https://api.minimax.cn/v1`。滴滴询价可另配置 `DIDI_MCP_KEY`，使用[滴滴个人账号控制台](https://mcp.didichuxing.com/)激活的正式MCP Key；缺省不阻断高德查询。启动器生成隔离宿主 profile 和应用私有配置，权限为 0600；凭据不进入 `bundle/`、Git、模型输入或日志。受信任的本地应用在运行时读取高德与 M3 Key，具体边界见[架构说明](docs/architecture.md#运行材料与开发记录)。

```sh
cd ~/Development/agentic26
make agent-bootstrap   # 应用固定定位与 Maps 选点覆盖并构建 OctoSense desktop
make agent-doctor      # 检查版本、配置及打包边界，不请求在线服务
make agent-init-demo   # 重置独立模拟来源及时间；会关闭本启动器的实例
make agent-dev         # 显示应用窗口，规划时请求真实设备定位
```

`agent-init-demo` 将日历航班设为两小时后，并生成独立笔记与带当前时间的位置记录。默认位置为宝安大仟里室外步道的模拟坐标，曾在上述真实查询中返回可行混合候选；实时结果可能变化。三份模板在 `demo/`，运行数据在 `.local-state/agent/` 的应用 jail 中；普通启动保留已编辑的日历与笔记，但正常模式不将它们作为任务来源；默认位置来自系统。使用 `make agent-demo` 才读取模拟位置；该模式位置超过 15 分钟会阻止规划，需明确执行初始化命令。

```sh
make agent-status
make agent-tree
make agent-logs
make agent-shot SHOT=build/debug.png
make agent-stop
make agent-hidden      # 相同接口，隐藏窗口，用于原生交互验收
make agent-demo        # 显式模拟定位演示；不会在真实定位失败后自动切换
make smoke             # 隔离数据与离线合成响应的行为检查
make check             # 同一锁定 Hub 的包预检；不替代真实任务验收
```

开发启动默认开启本机诊断记录。`make agent-trace` 查看当前可见应用实例的记录摘要，`make agent-trace-read` 输出完整事件，`make agent-trace-export` 导出到忽略的 `build/traces/`，同时生成状态文件；当前启动实例还附带宿主日志，便于查找不会进入脚本回调的原生错误。记录包括准备派发的模型请求正文、实际派发事件、收到的响应、工具参数和结果、生成源码、渲染诊断及本地地图事件，可按实例、查询和工具调用 ID 关联。原始记录包含位置与任务内容，仅供本机调试；凭据在写入前移除，不记录鉴权头。正式配置默认关闭，开发启动可用 `python3 tools/agent.py dev --no-trace` 关闭。

开发记录按1MiB文件上限分段追加。下次启动在停止原宿主后，将旧诊断完整迁至 `build/traces/archives/` 的私有目录并保留摘要；业务来源保持原位。显式历史读取也可定位唯一的归档记录，当前实例选择不会回退到归档。

读取工具从当前界面标识选择实例，不按日志修改时间猜测。没有唯一标识时明确报告；历史记录可用 `--trace-session <session> --trace-instance <vm-N>` 显式选择。导出状态标明记录缺失或读取期间实例变化；这些文件不用于行程恢复或下一轮模型上下文。

正式启动器在隔离目录生成本地 `.app` 并直接运行包内宿主，保留系统定位用途声明；不修改系统权限。

真实位置需取得 100 米以内精度、60 秒以内的系统样本，最多等待 15 秒；拒绝权限、不可用或精度不足时显示错误。坐标经高德转换，并独立核实起终点城市及计价依据。城市信息、费用或有效路线缺失时明确失败，不填入深圳或模拟答案。当前查询使用定位样本的真实采样时间，不能仅刷新时间伪造新位置。位置将用于高德坐标／城市／交通请求，并作为 Agent 工具观察发送给 M3。

修改应用后重新执行 `agent-dev` 或 `agent-hidden`。官方系统应用在编译时嵌入，启动器会重新打包、增量编译，并核对实际挂载源码，不能靠重启旧二进制加载新脚本。启动器只关闭它自己管理的实例。调试接口、运行版本和目录说明见[工具链说明](toolchain/README.md)。

旧 `make bootstrap`、`make doctor`、`make dev` 与 `make run-hidden` 仍保留为 App Hub card-host 路径，适合不需要宿主模型服务的隔离实验；完整 Navigation 使用上面的 `agent-*` 命令。两条工具链分别由 `toolchain/sources.lock.json` 与 `toolchain/agent-runtime.lock.json` 锁定，不修改个人全局模型配置。实时定位、Maps 选点、字体附属文档校验与低层控件寻址／尺寸的本地覆盖分别锁定，不能将带补丁运行称为未修改的 stock 宿主。字体许可和复现说明中的普通来源链接不作为运行资源；实际嵌入资源仍按主机权限检查。Maps 往返需要本仓库的宿主扩展，不是官方版本已有的跨应用契约；应用包仍为 OctoScript。包预检使用相同权限定义的锁定 Hub CLI，旧 card-host 的权限闭名单保持原样。

真实截图必须来自当前应用并查看后再更新 `bundle/screenshots/01-main.png`。包编辑后执行 `make check` 更新摘要；签名后的包不能直接沿用此编辑流程。历史初始化证据见[验证记录](docs/verification.md)，当前行为的验收证据见[动态界面任务包](tasks/agent-generated-ui/packet.md)，0.2 联动见[交互任务包](tasks/interaction-integration/packet.md)，0.1 与此前在线基线见[能力任务包](tasks/capability-boundary/packet.md)。
