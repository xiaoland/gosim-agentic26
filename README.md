# Navigation · 出行能力层

“40 分钟内到机场，预算 50，尽量便宜。”

这句话看起来简单，却包含了一个需要检索、计算和判断的任务：从哪里出发，去哪个机场，预算使用什么币种，有没有便宜且赶得上的接驳组合？用户没有指定机场或币种，系统只能从本次取得的位置、背景资料或有依据的假设中补足这些信息，并保留它们的来源。

Navigation 是 GOSIM Agentic App 2026 的出行作品，实现方向为**帝王蟹能力层**。我们希望把出行能力交给 Agent 使用，而不只是给地图套一层自然语言表单。地图擅长回答确定起终点之间怎么走；Agent 还需要结合目标与上下文，决定查什么、尝试什么组合，以及怎样向用户解释结果。当前先直连真实交通与报价服务，验证这条业务链，再逐步接入生态中的上下文能力。

## 产品目标

在时间和预算约束下，寻找尽可能便宜的出行方案。这里的“组合”不是分别比较全程公交和全程打车，而是探索步行、公共交通与打车之间的接驳：可以先打车到站、下车后换乘，也可以在公交前后或中段加入打车。

推荐只是结果的一部分。用户还应能查看已评估方案的分段、费用、用时、地图及限制；即使没有可行方案，也应知道哪些尝试不满足条件、依据是什么，以及改变哪些条件可能有帮助。未知票价、候车时间和未核实的连接不能被当成零成本或已经连通。

## 当前能力

Navigation 已实现一个自主工具循环、确定性的路线组合与比较，以及由同一 Agent 生成的原生界面。业务与呈现共用本次任务的消息历史，模型为 MiniMax M3，应用使用 OctoScript／Makepad Splash。

### Agent 选择行动，工具计算结果

标准 function-calling loop 保留模型返回的 `assistant.tool_calls`，按 `call_id` 执行工具，将结果作为 `role:tool` 消息提交，再继续模型。模型自行选择查询、多步探索、资料读取和呈现时机；没有工具调用时结束本轮。技能是按需读取的语言与能力资料，不是必须遵循的流程攻略，也没有固定的“先公交、再打车、最后展示”workflow。

`query_transit` 和 `query_driving` 取得供应商路线；`extend_route` 从本轮真实地点、站点或已查路线前缀继续检索下一段，逐步形成接驳图。Agent 决定扩展哪个节点、使用哪种交通方式，代码负责计算下一段出发时间、核对实际连接并累计费用。完整公交区间使用供应商返回的整段票价，不按距离或站数切摊；候车未知时，后续查询只能说明最早出发场景，不能保证接得上。

`compare_routes` 比较已经查到的范围，区分已知费用、预算状态、截止时间和连接未知项；`get_route` 与 `get_route_graph` 则按需读取已有方案详情或接驳图，不重新检索供应商。这种分工让模型负责探索与解释，让金额、时间和可行性保持可追溯的确定性计算。已查范围中的较优方案不等于现实全局最优。

### 业务与界面由同一个 Agent 编排

M3 不只选择交通工具，也编写实际 Makepad／Splash DSL。固定外壳保留输入与查询／终止入口，其余呈现由 Agent 组织，不是向预制路线卡片或固定五槽模板填 JSON。

`render_ui` 可以提交整稿，也可以一次提交一个或多个命名区块。后续只更新指定区块，未更新区块的脚本状态、输入和滚动位置保留。各区块拥有独立 Splash VM，通过本地事件使用当前真实事实；详情覆盖层、列表返回和多个地图可以组合，但位置、样式和区块数量由 Agent 决定。

执行诊断作为工具结果返回同一个循环，Agent 可以修正失败区块，不需要另一个展示模型循环。查看路线、切换详情和地图操作在本地响应；它们不会变成新一轮用户对话。开发态诊断记录保留实际请求、工具结果、生成源码和错误，供开发时区分模型遗漏、供应商失败与执行问题。

### 地图与报价保留供应商语义

`AutoNaviMapView` 提供原生地图视口和拖动、缩放交互。视口变化后，应用通过高德官方静态地图服务请求包含实际路线几何的新视口图像；拖动时有本地预览，刷新仍有网络延迟。这是静态服务驱动的交互地图，不是无缝瓦片地图或导航 SDK。高德每张静态图最多四条独立折线，Agent 可依据路径目录分步嵌入多个地图；应用不截断几何，也不跨缺口补线。

打车费用可使用高德估价，也可通过正式滴滴 MCP 接口搜索地点、取得多车型当前报价，并把选定报价关联到明确打车段，替换原估价后重新计算组合费用。不同供应商的地点对应依据、坐标差异、优惠条件和未知连接继续保留。询价不是下单，当前估价也不保证未来接驳时能够兑现。

## 实现范围与后续方向

当前每次输入都是独立查询，没有澄清问答、任务结果持久化或跨次恢复。正常运行使用实时位置，尚未接入真实日历、笔记或邮件账户；显式 demo 的位置、日历和笔记是独立模拟来源，交通与模型服务仍使用真实请求。未来希望通过用户授权的跨应用背景和偏好学习减少表达，并探索动态工具与子 Agent 协作；这些仍是愿景，不是当前能力。

应用运行在 macOS Apple Silicon 的锁定官方 OctoSense 宿主及本仓库覆盖上，手机交互检查使用宿主 Android 样式，不冒称 Android 真机验证。确定性工具和原生区块接口已经具备，但模型探索与生成质量仍有边界：可能遗漏方案详情、误读结论或生成不实用的界面。0.11.6 的区块与状态保留经过隔离原生检查，没有据此重新证明完整 M3 出行任务可靠性。
