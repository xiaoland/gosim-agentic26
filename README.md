这句话看起来简单，却包含了一个需要检索、计算和判断的任务：从哪里出发，去哪个机场，预算使用什么币种，有没有便宜且赶得上的接驳组合？用户没有指定机场或币种，系统只能从本次取得的位置、背景资料或有依据的假设中补足这些信息，并保留它们的来源。

Navigation 是 GOSIM Agentic App 2026 的出行作品，实现方向为**帝王蟹能力层**。我们希望把出行能力交给 Agent 使用，而不只是给地图套一层自然语言表单。地图擅长回答确定起终点之间怎么走；Agent 还需要结合目标与上下文，决定查什么、尝试什么组合，以及怎样向用户解释结果。当前先直连真实交通与报价服务，验证这条业务链，再逐步接入生态中的上下文能力。

## 产品目标

在时间和预算约束下，寻找尽可能便宜的出行方案。这里的“组合”不是分别比较全程公交和全程打车，而是探索步行、公共交通与打车之间的接驳：可以先打车到站、下车后换乘，也可以在公交前后或中段加入打车。

Navigation 将这个能力用于**出行目标守护**：用户确认到达期限、总预算和当前方案后，应用在前台核验目标是否仍能实现；原方案失效时重新探索，并在用户确认后才替换方案。守护的是用户目标，路线可以调整；不能擅自增加预算、推迟期限，也不保证现实交通一定准时。目标守护的实现与验收见[守护记录](tasks/journey-guardian/packet.md)，多出行与详情恢复见[出行列表任务](tasks/trip-list/packet.md)。

推荐只是结果的一部分。用户还应能查看已评估方案的分段、费用、用时、地图及限制；即使没有可行方案，也应知道哪些尝试不满足条件、依据是什么，以及改变哪些条件可能有帮助。未知票价、候车时间和未核实的连接不能被当成零成本或已经连通。

## 当前能力

Navigation 已实现一个自主工具循环、确定性的路线组合与比较，以及由同一 Agent 生成的原生界面。业务与呈现共用本次任务的消息历史，模型为 MiniMax M3，应用使用 OctoScript／Makepad Splash。

### Agent 选择行动，工具计算结果

应用通过配套宿主的 `model.chat` 提交单次模型请求，MiniMax 密钥由宿主持有；该接口是本仓库待上游接纳的扩展。标准 function-calling loop 保留模型返回的 `assistant.tool_calls`，按 `call_id` 执行工具，将结果作为 `role:tool` 消息提交，再继续模型。模型自行选择查询、多步探索、资料读取和呈现时机。M3 使用默认自适应思考，思考字段随完整 assistant 消息回传，用户结果只取回答内容。正常 stop 才结束本轮；截断、声明调用却缺失调用、没有正文也没有成功界面的回执均明确记为失败，不自动重试。技能是按需读取的语言与能力资料，不是必须遵循的流程攻略，也没有固定的“先公交、再打车、最后展示”workflow。

系统提示词保留任务目标和职责；工具说明提供正确调用所需的契约，实际结果保留费用范围、来源和未知项。模拟与真实模式共用同一分工：模型从原句或已读来源解释时限、预算与币种，工具检查结构化数值、币种和时间换算；相对时限从收到请求时起算，探索耗时也计入。目的地选择独立，不重新起算期限或改变预算，已确认的守护目标仍保持锁定。这一分工已有真实模型采用相对时限和中文数词预算的记录，绝对钟面时间的模型解释尚未覆盖。混合接驳、铁路班次、路线事实、目标守护和原生呈现由不同技能负责，首次只提供技能名称与适用说明，正文及案例通过 `read_skill` 按需取得。混合接驳技能引导模型识别已有路线的瓶颈，保留有价值的公共交通主干，再验证首段、末段或中段的替代走法；接驳数量不是目标，已有便宜方案满足要求时可以结束探索。

`query_route` 以 `transit`／`taxi` 选择公交查询或高德出租车估价；`extend_route` 从本轮 Route 与真实地点、站点继续检索下一段，逐步形成接驳图。查询、延长与附价使用同一种 Route 身份，Agent 引用路线和路段，代码保管耗时、金额与几何。Agent 决定扩展哪个节点、使用哪种交通方式，代码负责计算下一段出发时间、核对实际连接并累计费用。完整公交区间使用供应商返回的整段票价，不按距离或站数切摊；候车未知时，后续查询只能说明最早出发场景，不能保证接得上。

铁路使用 `search_rail_stations` 取得真实站身份，`search_rail_services` 查询具体班次、固定发到时刻及逐席别价格／余票，再由 `extend_route_with_rail` 接入同一种 Route。前后步行、公交或打车继续使用已有工具，模型无需复制时间、票价或坐标来拼方案。班次保留乘车日与列车始发日，错过发车后不能向后平移；地图到站不证明已通过安检、赶上检票或购得车票。当前来源是 12306 匿名网页查询，访问受限或格式变化时返回实际失败，不冒称官方开放 API。高德仍可提供公交化城际线路，但首末班时间不当作选定列车的时刻。真实 M3 已自主完成广州珠江新城到宝安 T3 标记入口的地铁＋S4831 城际＋步行方案：已知小计57元，包含候车的约258分钟；全程费用、站内衔接与安检仍未知。实际 Android 样式下的候选卡片、详情、接驳地图和保存已通过；恢复修复版本使用同一原始快照验证重启后查看与返回重开，未重新调用模型规划。在线与恢复验证的版本边界、原始失败及完整运行记录见[铁路接入任务](tasks/rail-integration/packet.md)。

`query_route` 回执保留路线范围、费用、时刻、评估和可继续接驳的节点引用；逐段事实由 `get_route(id)` 按需读取。地点搜索保留全部候选的身份、地址、城市与节点引用，采用目的地后提供该入口详情；节点完整坐标、来源与入口也可用 `get_route_graph(node_refs)` 读取。模型回执省去可按需取回的重复步骤和坐标，应用内部的 Route、地图与历史事实不变。这些信息供模型选择值得替换的片段，用 `query_route(to_ref)` 从当前起点查询到真实中转节点，再沿返回的 Route ID 用 `extend_route` 继续；省略 `to_ref` 仍查询整程。每段都实际查询完整供应商区间，不能从原公交总价中自行扣减或把站序当成新组合已经连通的证明。局部查询和多段累计已通过原生回归；真实 M3 配合受控交通数据，已自主查询“打车到中转站，再续接公共交通”，形成约10元／27分钟的完整混合候选，并保留候车未知；这证明一次接驳探索成功，不代表真实路况、多场景稳定性或完整界面交付已经验收。探索行为和验证范围见[接驳探索任务](tasks/transfer-exploration/packet.md)。

`compare_routes` 比较已经查到的范围，区分已知费用、预算状态、截止时间和连接未知项；`get_route` 与 `get_route_graph` 则按需读取已有路线详情或接驳图，不重新检索供应商。未完成路线也可查看真实路段与地图，但已查段小计不会被当成到目的地的全程价格。这种分工让模型负责探索与解释，让金额、时间和可行性保持可追溯的确定性计算。已查范围中的较优方案不等于现实全局最优。

守护事实另外公开“从当前时刻重新执行原完整方案”的计算范围，固定班次不会因出发变晚而平移。这个反事实判断不证明用户未出发、已经登乘或实际行程失败；缺少进度依据时在途状态仍未知。替代比较区分已查路段小计差额与整程费用差额，只有同范围且两边完整费用已知时才给整程差额，旧报价不变成新证据。首批改进与验证范围见[后续优化任务](tasks/semifinal-readiness/packet.md)。

较早验证中的真实 M3 实验在一次实际模型循环中完成条件替代闭环：从广州珠江新城重新核验旧计划，自主建立公交＋今日 S4837 城际＋步行的 Route，实际打开卡片、同路线详情和高德地图，再经父应用确认保存目标版本2。合成目标的18:41期限与200元预算保持；到 T3 官方入口的三段已查估价合计57元，站内衔接、设施内部通达与整程费用仍未知，确认不认证准时到达，也不下单。验证使用 macOS 宿主 Android 样式；位置与初始目标为隔离测试材料，模型、铁路与交通服务真实。

后续验证从真实已确认目标记录恢复，用新的位置观测启动前台重核，经条件确认保存版本2，再冷恢复，启动没有新增模型或规划调用；原期限、预算与已花费用保持。这是跨修复版本的接续证据，整程费用与目的地到达仍未知，模型自由文字也可能误写，不能当作完整可行性或准时保证。确切版本与验证范围归[后续优化任务](tasks/semifinal-readiness/packet.md)。

较早验证的部分未完成公交候选解释仍将已查终点时刻写成到 T3，并称期限、预算满足，实际权威评估为未知。后续实验还观察到用时误写和无依据的“一票制”解释；确定性事实正确不代表模型自由表述可靠。这项解释准确性未通过，不能将核心交互通过写成整轮质量全部通过。此前地图目录阻塞路线选择、真实大折线处理与布局误用均有保留的失败和定点修复证据；最新范围与原件归上述任务记录。

### 业务与界面由同一个 Agent 编排

M3 不只选择交通工具，也编写实际 Makepad／Splash DSL。外壳提供出行侧栏、输入与查询／终止入口；守护目标的确认、进度和核验由本地控件处理，方案呈现由 Agent 组织，不是向预制路线卡片或固定五槽模板填 JSON。

总结论、解释、方案列表、建议和方案详情各有独立的 `render_*` 工具，直接接收任意DSL。它们共用区块引擎，不规定调用顺序、布局或同类块数量；通用 `render_ui` 仍可提交额外内容或整稿。后续只更新指定区块，未更新区块的脚本状态、输入和滚动位置保留。每条路线自动取得可复用的 `polyline_*` 几何引用，地图在运行时解析完整坐标，模型无需传递折线；路线也明确标注当前几何目录是否已读，Agent 可用 `get_route` 取得实际路径目录并自主分图。各区块拥有独立 Splash VM，通过本地事件使用当前真实事实；详情覆盖层、列表返回和多个地图可以组合，但位置、样式和区块数量由 Agent 决定。

执行诊断作为工具结果返回同一个循环，Agent 可以修正失败区块，不需要另一个展示模型循环。渲染工具等待新稿的首次事实绑定完成，隐藏详情也不以“源码已安装”提前报告成功；这不保证所有后续交互都无错误。查看路线、切换详情和地图操作在本地响应；它们不会变成新一轮用户对话。开发态诊断记录保留实际请求、工具结果、生成源码和错误，供开发时区分模型遗漏、供应商失败与执行问题。 模型请求失败后，可在当前窗口点击“继续规划”，保留已有事实并续接失败请求，不重复执行已完成的工具；已关闭窗口的模型会话不恢复。 宿主为模型请求提供300秒HTTP等待，外层等待310秒；普通服务仍为120秒。真实恢复实验取得了约216秒和127秒的完整响应，说明旧120秒等待会截断这两次生成，但延长等待不保证服务一定成功。

后续隔离验收保留原消息与真实渲染错误，由 M3 自主修正候选卡片和滚动详情。使用同样原稿、历史交通事实与正式出行恢复界面，两条不同 Route 的卡片→详情→完整地图视口→返回已实际通过；详情浮层按结果区剩余高度测量，避免内部滚动被父容器裁切。最后的恢复交互检查没有重新调用模型或交通规划，只验证首组实际地图路径，不证明全部分图或静态推荐解释准确。


界面提供卡片容器、标题、正文、辅助文字和操作等七种通用样式，借鉴 Material 3 的层级与状态设计；它们不选择路线，也不是预制 RouteCard 或完整 Material 组件库。通用定义已整理为 [agentic-native-ui 源码包](packages/native-ui/README.md)，通过构建期物化消费，并保留 Navigation 的 Nav 别名和局部字体。Navigation 的普通正文、辅助文字与标题默认字号分别为16、14、22；出行页长标题采用18号字并允许两行，以适应手机视口。独立 `material-ui` 技能负责通用原生呈现，`native-ui` 保留本应用的事实与地图适配。[独立笔记示例](examples/native-ui-notes/README.md)用公开合成资料验证同包的列表、详情、返回、内容更新及 Android 样式浅／深色重应用。另一次隔离 M3 实验已实际按需读取通用技能和两份语法／原语资料，自行生成可读的双记录列表，完成详情、更新和返回；原始生成稿未被手改。实验经历多次诊断修正，不代表首稿稳定性；其工具与模型传输是实验适配器，不冒称官方 standalone card-host 的模型接口，也不读取个人 Notes。Agent 可以自由组合候选卡片、地图和详情，并按同一 Route 的事实更新内容。新界面默认随内容自然增长，由外层滚动；需要自行管理有限视口时显式选择 viewport。尺寸约定随区块保存，旧稿保持原有规则。

### 出行列表与详情主页

侧栏列出已保存的出行，可新建、选择或删除；手机视口使用可收起的左侧抽屉，主页显示当前出行详情。普通规划提交后即建立记录，不需要先确认守护目标。查询结果和已确认目标属于同一条出行，切换时取消当前查询，迟到回调不能写入另一条出行。

重新打开或选择历史出行只恢复展示，不自动调用模型。成功生成的界面区块、路线和对应事实用于还原卡片、详情与地图，页面标明历史时间；旧报价和交通依据不是当前有效证据。模型对话与未确认提案不恢复，重新规划或核验建立新的工具循环。旧版本保存的单个守护目标会迁移为一条出行。

历史详情以路线内容为主，输入默认收起；“调整要求”可展开原要求并新建规划。守护区优先显示期限、余额和核验状态，完整依据与进度按需展开。侧栏提供选中态和关闭遮罩，删除前确认具体出行；这些固定交互不限制 Agent 生成结果的布局。设计依据与前后实际截图记录见[基础界面优化](tasks/ui-ux-foundation/packet.md)。

### 用户确认目标，前台重新核验

Agent可以提出保存目标与选定路线，也可让生成的候选按钮通过本地操作准备所选方案的提案；两者共用同一提案函数，不续模型对话。应用先显示方案、费用与到达范围及关键未知，用户展开提案后查看完整期限、预算、偏好和依据，再点击确认保存。新提案重新折叠，避免沿用上一份提案的展开状态。替代方案同样先作为提案，拒绝不会替换已确认方案。查看本轮候选后，也可通过本地“用当前查看方案准备替代”入口提出选择，再点击确认；无需向模型发送第二句话。进度和累计已花费用由用户在本地入口确认，预算余额由工具计算，位置不能证明已经乘车或付费。

选择带有活动目标的出行后，可以点击“重新核验”；启动和切换只读取历史详情。模型重新获取当前位置及交通证据，绝对期限不重新起算，已花费用不会被当作可用预算。结果区分估计成立、明确失效和证据不足；新查到另一条路线只作为替代候选。第一版不逐段推断在途进度，有进度而缺少剩余路段证据时会保留未知状态。结束目标后保留出行历史；删除守护目标与删除整条出行是不同操作。

普通规划结果和确认后的守护状态均按出行保存，未确认提案不持久化。用户应主动核验；这里没有后台监听、自动下单或准时保证。本轮完整交互和真实服务验收以[守护任务记录](tasks/journey-guardian/packet.md)为准。

### 地图与报价保留供应商语义

`AutoNaviMapView` 提供原生地图视口和拖动、缩放交互。视口变化后，应用通过高德官方静态地图服务请求包含实际路线几何的新视口图像；拖动时有本地预览，刷新仍有网络延迟。这是静态服务驱动的交互地图，不是无缝瓦片地图或导航 SDK。高德每张静态图最多四条独立折线，Agent 可依据路径目录分步嵌入多个地图；应用不截断几何，也不跨缺口补线。

打车费用可使用高德估价，也可通过正式滴滴 MCP 接口搜索地点、取得多车型当前报价。`attach_quote` 直接引用已查 Route 的打车 leg，替换该段估价并返回新 Route；旧路线保留，展示和比较明确选择新 ID，无须为附价重新查询路段。派生路线保留原耗时、几何与完成状态，不把报价成功当成连接已核实。滴滴同时返回原价与优惠价时，以优惠价作为本次有效估价，并保留原价供对照；用户已确认该优惠无需另行资格。不同供应商的地点对应依据、坐标差异和未知连接继续保留。询价不是下单，当前估价也不保证未来接驳时能够兑现。

## 实现范围与后续方向

每次新规划仍使用独立模型会话，没有澄清问答。宿主模型请求失败后，同一窗口、同一出行且输入未改时可点击“继续规划”，沿用已完成工具结果和原到达期限，仅补充当前时间；不自动重试、不重放已完成工具，也不把旧报价改成新查询。修改输入、取消、切换出行或关闭应用后不再续接该模型会话。出行列表保存历史结果和用户确认后的守护状态；重新规划与核验不恢复旧对话，也不会把历史页面当作新查询证据。正常运行使用实时位置，新增背景工具读取用户授权并选定的系统日历，以及已打开的 OctoSense Notes。Agent 自主选择日历时间窗，或先搜索笔记再读取原文；来源保留原始字段、时区、修改时间与查询范围，不预先合成行程背景。未授权、未选择、未打开、空结果和截断分别返回，不阻止明确目的地的规划。

背景接入已验证真实未授权拒绝，以及隔离环境中通过 Notes 原生界面创建测试笔记后的搜索、读取链；真实个人日历和笔记仍待用户授权验收。Notes 调用复用官方共享工具中转，但需要本项目宿主的薄接口扩展；不读取其它应用存储，也不是 macOS Apple Notes。尚未接入邮件账户。显式 demo 的位置、日历和笔记仍为独立模拟来源，交通与模型服务使用真实请求。跨任务偏好学习、动态工具与子 Agent 协作仍是后续方向。

完整能力运行在 macOS Apple Silicon 的锁定 OctoSense 配套宿主上，已升级至 2026-10-11 发布的官方 RC6（`f9f6fea9`），配套覆盖与构建版本由锁文件维护。交互检查使用 Android 样式，不冒称真机验证。针对初赛反馈，官方原版 card-host 已能显示首屏和能力缺失说明，缺少必要扩展时查询不可用；完整定位、模型、动态区块与地图能力仍需配套宿主，首屏降级通过不等于 App Hub 完整安装验收。

0.16.0 的出行列表已通过27项原生交互回归，覆盖迁移、切换、历史界面与地图事件、重启和删除；原有守护流程另有32项回归。历史恢复还修复了配套宿主增量加载中文源码时的字节边界崩溃，实际中文滚动区恢复可见。验证使用 macOS 宿主 Android 样式，合成路线与测试地图不冒称真实交通；一次真实 M3 规划生成的7条路线与3个界面区块已保存，重启后实际高德地图纹理仍可显示，恢复没有新增模型或交通规划调用；完整条件见[出行列表任务](tasks/trip-list/packet.md)。

0.15.0 的真实 M3／高德验证走过初次规划、用户确认、费用更新和重新核验：保持200元总预算及原绝对期限，确认已花190元后重新取得5条候选，工具将原计划判为证据不足。机场末段约312米未取得直接接驳依据，因此没有冒称可行或自动替换原路线。原生回归另覆盖替代确认、拒绝、重启恢复、损坏记录恢复和删除。动态界面的已知零高度布局会得到针对性诊断，详情层也随固定目标区更新位置；这些证据不保证模型每次都生成完善界面。实际条件与剩余范围见[守护任务](tasks/journey-guardian/packet.md)，模型迁移历史见[初赛反馈任务](tasks/runtime-upgrade/packet.md)，路线计算依据见[路线任务](tasks/route-identity/packet.md)。
