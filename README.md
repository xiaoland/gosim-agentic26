# Navigation · 一句话出行 Agent

Navigation 是 GOSIM Agentic App 2026 的出行作品，实现方向为**帝王蟹能力层**。用户给出时间、预算和偏好，Agent 自主查询交通、探索接驳组合，用确定性代码比较方案，再生成可交互的原生界面。

典型输入是：**“40 分钟内到机场，预算 50，尽量便宜。”** 这句话没有指定机场、出发位置或币种；这些信息须来自本次取得的位置、背景资料或有依据的假设，不能默认补成深圳机场和人民币。

应用源码在 [`bundle/`](bundle/)，使用 OctoScript／Makepad Splash；模型为 MiniMax M3。当前可复现运行目标是 **macOS Apple Silicon 上的锁定官方 OctoSense 宿主及本仓库覆盖补丁**，交互检查使用宿主的 Android 手机样式，尚不是 Android 真机或 APK 验证。

## 产品目标

在用户给定的时间和预算内，寻找尽可能便宜的出行方案，包括步行、公交、地铁与打车的混合接驳。系统不仅应给出推荐，还应让用户查看已评估方案的分段、费用、用时、地图和限制；没有可行方案时，也应说明各方案不满足条件的具体依据。

Agent 负责理解目标、选择查询和解释结果；代码负责累计费用、计算到达时间并判断条件。未知票价、候车时间、断段或未核实的末端接驳不会被当成零成本或已经连通，也不会因模型称“可行”就改变计算结果。

当前每次查询都是独立任务，没有澄清问答、结果保存、跨次恢复或长期记忆。真实日历、笔记、邮件账户尚未接入。长期方向是利用用户授权的上下文减少表达，但这些账户能力不属于当前交付。

## 当前能力

- **自主查询与混合探索。** Agent 可查询公交和驾车，也可从本轮真实地点、公交站和已取得路线前缀继续延长步行、出租车或公共交通区间。它可以探索公交前后打车、中段接驳等组合，不限演示城市，也没有宿主预设的必调顺序。
- **确定性比较。** 代码计算已查方案的费用、时间和原始截止条件，保留来源、估价性质、未知项与失败原因。完整公交区间使用供应商返回的整段价格，不按比例切摊票价；高德打车估价不是滴滴实时价格。
- **可选滴滴询价。** 使用正式 MCP Key 搜索滴滴地点并取得多车型当前估价，可将所选报价关联到明确打车段、替换原估价并重算组合费用。优惠单列；不同供应商的地点对应依据、坐标差异和未来上车价格的不确定性保留。没有下单功能。
- **Agent 生成原生界面。** 固定外壳只有输入和查询／终止入口。Agent 编写任意 Makepad／Splash DSL，可一次提交一个或多个命名区块，追加或只替换指定区块，保留其它区块的输入、滚动和本地状态。详情可使用独立覆盖层，关闭后返回原列表；没有预制业务卡片或固定五槽模板。
- **原生地图与分图。** AutoNaviMapView 支持拖动、双击或按钮缩放、全路线取景。地图视口变化后通过高德官方静态地图服务刷新新区域和同源路线，具有网络延迟，并非无缝瓦片地图；尚未支持双指捏合。高德每张静态图最多四条独立折线，Agent 可按完整目录分步嵌入多个地图，应用不截断路线或跨缺口补线。
- **本机开发诊断。** 可关联实际模型输入、工具调用与结果、生成源码、渲染诊断和地图事件，区分模型遗漏、供应商失败与执行错误。记录不用于恢复任务或下一次模型上下文。

这些是已实现的接口与计算能力，不是每次模型输出都会完整呈现的保证。当前仍可能出现模型探索不足、忽略计算结论、生成语法错误、遗漏地图／详情或排版不实用。应用不提供强制补齐组件或第二个展示模型循环；执行错误作为工具结果返回给同一 Agent，由它决定修正。

## Agent 如何工作

Navigation 使用一个标准 function-calling loop，业务与展示共享本次消息历史。模型返回的 `assistant.tool_calls` 按 `call_id` 执行，所有工具结果以 `role:tool` 提交后继续请求模型；没有工具调用时结束本轮，等待下一次独立查询。用户可终止，旧查询的迟到响应不会续接新任务。

| 工具范围 | 实际作用 |
| --- | --- |
| `read_location`、`search_places`、`adopt_destination` | 取得位置、搜索真实地点并采用有依据的目的地。 |
| `query_transit`、`query_driving`、`extend_route` | 查询交通或延长真实路线前缀；费用和时间由代码计算。 |
| `search_didi_places`、`quote_didi`、`attach_quote` | 搜索报价地点、询价、将指定车型估价关联到打车段，不叫车。 |
| `compare_routes`、`get_route`、`get_route_graph` | 比较已查范围，按需取得完整方案分段或接驳图，不重复查询供应商。 |
| `read_skill`、`render_ui` | 按需读取实际语言／数据资料，提交原生源码并取得执行诊断。 |

这不是固定的“先计划、再查公交、再查打车、最后渲染”workflow。模型自己选择工具、多步检索及界面组织；技能是按需材料，不是必须先读的流程攻略。`render_ui({source})` 替换整稿，`render_ui({blocks})` 更新指定区块；各块共享当前真实事实，拥有独立脚本状态和地图绑定。

真实请求的等待、模型推理和修稿都会消耗用户原始时间条件。已查询候选的比较不等于现实全局最优，供应商估计耗时也不等于保证准时抵达。实现细节见[架构说明](docs/architecture.md)，工具与呈现材料见[路线技能](bundle/assets/skills/navigation_data.md)和[原生界面技能](bundle/assets/skills/native_ui.md)。

## 从仓库运行

### 环境与凭据

需要 macOS Apple Silicon、可用图形会话、Git、Rust stable 和 Python 3.9+。首次构建需要网络、数 GB 磁盘空间和编译时间；锁定上游源码放在仓库同级目录，不进入应用包。

先克隆仓库；已有本地检出可跳过：

```sh
git clone https://github.com/xiaoland/gosim-agentic26.git
cd gosim-agentic26
```

在仓库根目录新建 Git 忽略的 `.env`，将占位值换成自己的 Key：

```dotenv
MINIMAX_API_KEY=YOUR_MINIMAX_API_KEY
MINIMAX_BASE_URL=https://api.minimax.cn/v1
MINIMAX_MODEL=MiniMax-M3
AMAP_API_KEY=YOUR_AMAP_WEB_SERVICE_KEY
# 可选：正式滴滴个人 MCP Key；缺省仍可使用高德
DIDI_MCP_KEY=
```

M3 和高德 Web 服务 Key 是必需项；滴滴 Key 可从[滴滴 MCP 控制台](https://mcp.didichuxing.com/)获取。启动器检查固定模型和服务地址，不静默切换模型。凭据只写入本机私有配置，不进入应用包、Git、模型输入或开发导出；不要提交 `.env`。

### 默认：实时位置

在仓库根目录执行：

```sh
make agent-bootstrap
make agent-doctor
make agent-dev
```

`agent-bootstrap` 准备锁定源码、应用必要覆盖并构建宿主；`agent-doctor` 检查配置和构建身份，不请求在线服务；`agent-dev` 打包当前 `bundle/` 并打开 Navigation。每次启动会停止此启动器管理的旧实例，不影响其它应用实例。

默认请求系统实时位置。macOS 定位授权由用户决定，应用不会在失败后偷偷切到演示位置。获权后开始一次最长 15 秒采样，样本需满足精度和新鲜度要求；拒绝权限、定位不可用或样本不足会明确返回失败。位置与查询内容用于 M3 和高德请求，可选询价还会使用滴滴地点服务。

打开宿主顶栏样式菜单选择 **Android**，或使用 `⌘Space` 输入 `android` 后回车。启动器默认样式不是 Android，需明确切换；这是桌面宿主提供的手机布局模式。

### 显式演示

若评审环境无法取得系统位置，可明确使用演示模式：

```sh
make agent-init-demo
make agent-demo
```

初始化会停止此启动器的实例并重置三份独立模拟来源：公开地点的出发位置、日历航班和机票笔记。模拟位置默认位于深圳宝安大仟里附近，航班模板时间设为两小时后；这些不是评审者的真实 GPS 或个人行程。M3、高德以及已配置的滴滴服务仍是在线真实请求。

演示位置超过 **15 分钟**会过期，需再次明确初始化。普通实时模式不读取演示日历／笔记，也不依赖演示初始化；不会把模拟背景伪装成真实来源。模板见 [`demo/`](demo/)。

## 建议的人工验收

1. 确认当前仓库版本、Key 配置和运行模式，切到 Android 样式；输入“40 分钟内到机场，预算 50，尽量便宜。”并查询。
2. 核对目的地与计价依据：机场和币种是否来自已取得的事实或明确假设；demo 的位置、日历和笔记是否如实标注。
3. 查看本次结论与已评估方案。预期可理解费用、用时及条件依据；没有可行方案时，应能查看失败原因，不能把未知等待或未连接末段称为保证到达。
4. 若界面提供方案卡片／详情入口，点击不同方案，核对分段、费用、限制与地图目标；详情滚动后返回，列表和输入状态应保留。地图拖动／缩放可能等待供应商刷新，失败应显示实际原因。
5. 查询过程中可点击终止，确认运行状态结束；再次查询是新任务，不读取前次结果。不要以旧任务的界面或时间当作新任务成功。

呈现目标是结论、简明依据、可查看的方案列表、改进建议和各方案详情，但 Agent 决定布局与提交区块，宿主不强制生成这些区块。因此“工具接口支持”和“本次实际交付完整”需要分开验收；地图控件存在也不等于地图服务加载成功。

### 已执行验证的范围

真实 M3／高德正常工具循环曾取得候选并生成可交互界面，也出现过缺分段、失效按钮、内容遗漏和计算结论误读。当前不能据此声明完整出行规划或生成界面普遍可靠；具体样本条件与诊断见[查询交付](tasks/query-delivery/packet.md)和[性能任务](tasks/agent-performance/packet.md)。

真实混合工具联调取得过打车→公共交通→步行的已查部分 23 元，但超过 40 分钟且没有连接原机场 POI，属于可解释的失败尝试。滴滴真实询价与报价替换计算分别有证据，不代表同一 M3 查询自动完成全部组合。详见[混合路线任务](tasks/mixed-routing/packet.md)。

**0.11.6 的增量区块验证使用隔离合成数据与真实原生控件，没有追加 M3 或交通服务请求。** 检查覆盖局部替换、状态保留、跨块详情、地图名字隔离、错误修正及内容区裁剪；不能据此保证模型采用区块或完整呈现。准确源码与证据边界见[区块任务](tasks/ui-blocks/packet.md)。旧截图不作为当前版本的效果承诺。

## 调试与仓库入口

```sh
make agent-status
make agent-trace           # 当前可见实例的脱敏记录摘要
make agent-trace-export    # 导出已有完整记录到忽略的 build/traces/
make agent-stop            # 只停止此启动器管理的实例
make check                 # 应用包预检，不替代真实任务验收
```

开发启动默认开启本机 trace，普通正式配置默认关闭。关闭开发记录可用 `python3 tools/agent.py dev --no-trace`。原始导出仍包含位置、任务和生成源码，应留在私有忽略目录；它不参与业务恢复。诊断记录保留完整实际请求／响应、工具和原生错误，导出状态明确记录不完整的情况。

完整构建、隔离检查、trace 历史选择、截图及宿主补丁操作归[工具链说明](toolchain/README.md)。应用源码在 [`bundle/`](bundle/)，包装器和原生测试在 [`tools/`](tools/)，上游锁与覆盖在 [`toolchain/`](toolchain/)。协作规则见 [AGENTS.md](AGENTS.md)，长期知识与各任务证据入口见[文档导航](docs/index.md)。
